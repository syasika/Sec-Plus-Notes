## Introduction

### Non-Repudiation
Non-repudiation is the inability to deny having performed an action or made a statement. It means "you can't deny what you've said" – there's no taking it back.

- **In Cryptography**: Ensures that when someone sends data to a third party, that third party can verify the data truly came from the sender.
- **Analogy: Signing a Contract**
  - Your signature adds non-repudiation.
  - It proves you really did sign the contract.
  - Others can see your signature and confirm the origin.

### Key Concepts

#### Proof of Integrity
Proof of integrity ensures that information remains accurate and consistent over its lifecycle. 

- **Method: Hashing**
  - **Hash**: A cryptographic function that represents data as a short, fixed-length string of text (also known as a message digest or fingerprint).
    - **Key Property**: If *any* data changes, the hash changes drastically.
      - *Analogy*: If the person changes, you get a different fingerprint.
  - **Limitation**: A hash alone doesn't necessarily associate data with an individual. It only tells you if the data has changed.

- **Hashing Example: Gutenberg Encyclopedia, Vol 1 (8.1 megabytes)**
  - Original hash (example): `c7004997a9cff73f9c3423579be5e8577389b63b4b085e541d327903f99a09db`
  - If *one character* is changed anywhere in the 8.1 MB file, the hash changes completely (example): `5c82dcc2e0f359b48fddd71f6ca4602941f5e21e26b2edc7bb43942eb715a1c1`
  - **Conclusion**: If the hash is different, something has changed, and data integrity has been compromised.

#### Proof of Origin
Proof of origin ensures that the source of a message can be verified. 

- **Method: Digital Signatures**
  - A digital signature makes sure the signature isn't fake, providing non-repudiation.
    - **Signing**: The message is signed using the sender's private key.
      - The message itself doesn't need to be encrypted to be signed.
      - Only the sender possesses their private key; nobody else can sign with it.
    - **Verification**: The signature is verified using the sender's public key.
      - Any change to the message will invalidate the signature.
    - **Result**: Provides assurance that the information received is not only the same as what was sent (integrity) but also that it had to be sent by the person who provided the digital signature (origin/non-repudiation).

## Digital Signature Process

### Example: Alice Sending "You're hired, Bob" to Bob

1. **Plaintext Message**: Alice starts with her message ("You're hired, Bob").
2. **Hashing Algorithm**: Alice's computer runs the plaintext through a hashing algorithm.
3. **Hash of Plaintext**: A unique hash (message digest/fingerprint) is generated.
4. **Encryption with Private Key**: Alice's computer then encrypts this hash using Alice's private key.
   - *Crucial Point*: Only Alice has her private key, so only she can perform this encryption.
5. **Digital Signature**: The encrypted hash is now the digital signature.
6. **Transmission**: Alice sends the original plaintext message along with the digital signature to Bob.
   - The message itself isn't encrypted, only the hash of the message is encrypted to form the signature.

### Verifying a Digital Signature (Bob Receiving Alice's Message)

1. **Receive Message**: Bob receives the plaintext message and the attached digital signature.
2. **Decrypt Digital Signature**: Bob uses Alice's public key to decrypt the received digital signature.
   - *Crucial Point*: Alice's public key is publicly available and can decrypt anything encrypted with her private key. If it decrypts successfully, it confirms Alice's private key was used.
3. **Hash of Plaintext (from sender)**: The decryption process yields the original hash that Alice created.
4. **Hash Received Plaintext**: Bob takes the received plaintext message and runs it through the same hashing algorithm that Alice used.
5. **Hash of Plaintext (from receiver)**: This generates a new hash of the received plaintext.
6. **Compare**: Bob compares the hash obtained from decrypting the digital signature with the hash generated from the received plaintext.
7. **Result**:
   - **If the hashes match**:
     - **Proof of Integrity**: The message has not been changed since Alice signed it.
     - **Proof of Origin (Non-repudiation)**: Because Alice's public key successfully decrypted the signature, and the hashes match, it proves that only Alice (with her private key) could have created that specific signature for that specific message. Alice cannot deny sending the message.
   - **If the hashes do not match**:
     - Either the message was altered in transit (integrity compromised) or the signature was created by someone other than Alice (origin/authentication compromised).

## Key Definitions

- **Non-Repudiation**: The assurance that someone cannot deny the validity of something (e.g., sending a message or signing a contract). It combines proof of integrity and proof of origin.
- **Proof of Integrity**: Guarantee that data has not been altered or tampered with.
- **Proof of Origin / Authentication**: Guarantee that the sender of a message is who they claim to be.
- **Hash / Message Digest / Fingerprint**: A fixed-size output of a hashing algorithm, unique to the input data. Used to detect data alteration.
- **Digital Signature**: A cryptographic mechanism using asymmetric encryption (private/public key pairs) to provide both proof of integrity and proof of origin (non-repudiation).
- **Private Key**: A secret key known only to the owner, used for signing digital signatures (and decrypting messages in asymmetric encryption).
- **Public Key**: A publicly available key associated with a private key, used for verifying digital signatures (and encrypting messages in asymmetric encryption).

## Key Relationships & Mechanisms

- **Hashing provides integrity**. A hash changes if *any* part of the data changes.
- **Digital signatures provide non-repudiation** by combining hashing with asymmetric encryption.
- A **private key** is used to create a digital signature.
- A **public key** is used to verify a digital signature.

## Digital Signature Process

### Creation
1. Sender creates a plaintext message.
2. Sender's computer generates a hash of the plaintext.
3. Sender's computer encrypts this hash using the sender's private key. This encrypted hash is the digital signature.
4. Sender sends the original plaintext message and the digital signature.

### Verification
1. Receiver's computer decrypts the received digital signature using the sender's public key to get the original hash (from sender).
2. Receiver's computer generates a new hash of the received plaintext message.
3. Receiver's computer compares the two hashes.
4. If they match, non-repudiation (integrity and origin) is confirmed.

## Important Distinctions

- A **hash** only proves integrity (that the message hasn't changed). It doesn't prove who sent it.
- A **digital signature** proves both integrity (via the hash comparison) and origin (because only the sender's private key could have created a valid signature verifiable by their public key).
