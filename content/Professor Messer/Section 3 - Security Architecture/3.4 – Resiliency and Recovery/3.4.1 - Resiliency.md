# Resiliency Concepts

## Introduction to Resiliency

**Focus:** Maintaining uptime and availability of systems in information security.

**Resiliency:** The ability of a system to recover from failures and continue functioning.

**High Availability (HA):** A key method to provide resiliency. HA ensures that systems are always on, always available, without requiring manual intervention for recovery.

## High Availability (HA)

### Distinction from Simple Redundancy

- **Redundancy:** Having backup components but needing manual intervention (e.g., powering on, configuration) to become active, leading to downtime.
- **High Availability (HA):** Systems are always on and available. If one system fails, another immediately takes over.

### Characteristics of HA

- **Always on, Always Available:** Seamless failover ensures continuous operation even if a component fails.
- **Multiple Components Working Together:** Systems are designed to operate in parallel.
- **Active/Active Configurations:** Provides scalability by distributing load across all active components.

### Costs

- Higher availability almost always means higher costs.
  - Additional components (duplicate hardware).
  - Upgraded power infrastructure.
  - High-quality server components.
  - More complex configurations and maintenance.

## Server Clustering

**Concept:** Combines two or more servers to appear and operate as a single, large server from the user's perspective.

- **User Perspective:** Users see only one device (the cluster), not individual servers.

### Benefits of Server Clustering

- **Increased Capacity and Availability:** Easily add or remove servers in real-time.
- **Automatic Failover:** If a server fails, others pick up the load.

### Configuration

- Usually configured within the operating system.
- All devices in the cluster commonly use the same OS for interoperability.

### Shared Storage

- Servers in a cluster typically don't write to local drives.
- Use a separate, shared storage directory to ensure all servers have up-to-date, synchronized data.

## Load Balancing

**Concept:** Distributes incoming network traffic (load) across multiple servers.

### Key Difference from Clustering

- The servers in a load-balanced setup are often unaware of each other.
- A central load balancer manages which devices receive which requests.

### Flexibility and Scalability

- Servers can run different operating systems (e.g., Windows, Linux).
- Add or remove devices as needed to scale capacity.
- Automatically remove any servers not responding for failure detection.

## Site Resiliency

**Concept:** Having a prepared recovery site to take over operations in case of a disaster at the primary location.

### Process

1. **Recovery Site Prep:** Infrastructure is ready.
2. **Data Synchronization:** Critical data is replicated to the recovery site.
3. **Disaster Triggered Failover:** An event (e.g., natural disaster, major outage) triggers the need for failover.
4. **Business Processes Failover:** Operations switch to the alternate processing site.
5. **Primary Site Repair:** The primary site is repaired (can take hours, weeks, or longer).
6. **Revert Back to Primary Location:** Operations eventually switch back.

### Documentation

- The entire failover and failback process must be thoroughly documented and tested.

## Hot Site

**Description:** An exact replica of the primary data center.

### Characteristics

- **Duplicate Everything:** Hardware, software, and data are mirrored.
- **Stocked with Hardware:** All necessary equipment is on-site.
- **Constantly Updated:** Applications, software, and data are continuously replicated (automated replication).
- **High Cost:** Requires significant investment in duplicate infrastructure and ongoing maintenance.

### Recovery Time

- Minimal downtime; "flip a switch" and everything moves.

## Cold Site

**Description:** An empty building with basic infrastructure (power, lighting, HVAC).

### Characteristics

- **No Hardware:** No servers, network equipment, etc.
- **No Data:** Data must be brought from backups.
- **No People:** Staff must be transported to the site.
- **Lowest Cost:** Least expensive option to maintain.

### Recovery Time

- Longest recovery time (weeks to months) due to the need to acquire, install, and configure hardware, restore data, and staff the site.

## Warm Site

**Description:** Somewhere between a cold and a hot site.

### Characteristics

- **Enough to Get Going:** Has a big room with rack space, some basic hardware (e.g., network gear, some servers).
- **Partial Data Availability:** Some data might be available but often needs restoration.
- **Bring Hardware and Data:** You need to bring additional hardware, data, and staff.
- **Mid-range Cost:** More expensive than a cold site, less than a hot site.

### Recovery Time

- Moderate recovery time (days to weeks).

## Geographic Dispersion

**Concept:** Recovery sites should be physically distant from the organization's primary location.

### Purpose

- To mitigate the impact of large-area disruptions.
  - Examples: Hurricane, tornado, floods, earthquakes, regional power outages.
- If both locations are too close, a single event could affect them both.

### Logistical Challenges

- **Transporting Equipment:** Moving hardware to the recovery site.
- **Getting Employees On-Site:** Staffing the remote location.
- **Reverting Operations:** Reverting operations once the primary site is restored.

## Platform Diversity

**Concept:** Using many different platforms (e.g., Linux for servers, Windows for clients) to spread risk and reduce the impact of a single vulnerability.

### Rationale

- Some security issues are known and patched, while others remain undiscovered.
- Many vulnerabilities are specific to a single operating system.
- An exploit targeting one OS would not compromise systems running different OSes.

### Benefits

- Spreads the risk around.
  - Reduces exposure to a single vulnerability.
  
## Multi-Cloud Systems

**Concept:** Utilizing multiple cloud providers (e.g., Amazon Web Services, Microsoft Azure, Google Cloud) for services and data.

### Rationale

- **Cloud Outages Can Happen:** Major cloud providers experience downtime.
- **Geographically Dispersed Data:** Data and applications are spread across different providers and regions within those providers.

### Benefits

- **Increased Availability:** If one cloud provider experiences an outage, services can failover to another provider.
- **Enhanced Security:** A breach with one provider would not affect services or data hosted on other providers.
- **Comprehensive Contingency Planning:** Planning for every contingency, including cloud-specific disruptions.

## Continuity of Operations Planning (COOP)

**Concept:** A plan for how an organization will continue to operate during and after a disruption when normal technological processes are unavailable.

### Problem

- We rely heavily on computer systems. Disasters can cause outages.
- There needs to be an alternative, often non-technical way to perform critical business functions.

### Solutions

- **Manual Transactions:** Recording sales or other activities on paper.
- **Paper Receipts:** Providing physical proof of transactions.
- **Phone Calls for Transaction Approvals:** Manually verifying credit cards or other approvals.

### Importance

- These alternative processes must be documented and tested before a problem occurs.
  - Ensures employees know exactly what to do during a technological outage.

## Takeaways for an Exam

1. **Distinguish between Redundancy and High Availability (HA):** Redundancy is having backups; HA means continuous operation with automatic failover. HA is "always on, always available."
2. **Understand the Cost of HA:** Higher availability directly correlates with higher costs due to duplicate hardware, robust infrastructure, and complex management.
3. **Differentiate Server Clustering and Load Balancing:**
   - **Server Clustering:** Multiple servers acting as one logical unit, sharing state (often via shared storage), and aware of each other. Good for tightly coupled applications.
   - **Load Balancing:** Distributes traffic across multiple independent servers, which are generally unaware of each other. Good for stateless or loosely coupled web services.
4. **Know the Three Types of Recovery Sites (and their trade-offs):**
   - **Hot Site:** Exact replica, fully operational, minimal downtime, highest cost.
   - **Warm Site:** Partially equipped, some data, moderate downtime, medium cost.
   - **Cold Site:** Empty shell, basic infrastructure only, longest downtime, lowest cost.
5. **Understand Geographic Dispersion:** Recovery sites must be physically separate to protect against regional disasters (e.g., hurricanes, floods). Be aware of the logistical challenges this introduces (transport, personnel).
6. **Explain Platform Diversity's Role in Security:** Using different operating systems and platforms reduces the risk of a single vulnerability compromising the entire infrastructure. It is about "spreading the risk."
7. **Grasp Multi-Cloud Strategy:** Using multiple cloud providers enhances resiliency against cloud-specific outages or breaches. Data and services are dispersed both geographically and across different cloud vendors.
8. **Define and Justify Continuity of Operations Planning (COOP):** COOP is essential for maintaining critical business functions when technology completely fails. It focuses on non-technical, manual alternatives. Emphasize the need for prior documentation and testing of these manual procedures.
