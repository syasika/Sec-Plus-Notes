# Backups

## Overview
- **Definition**: Essential for recovering valuable data and planning for disaster scenarios, backups are a critical component of any IT strategy.
- **Purpose**: Facilitate quick recovery if data is lost.

## Backup Planning Factors
- **Total Amount of Data**: Ranges from few MBs to many TBs/PBs.
- **Type of Backup**:
    - Full backups: Complete copy of all data.
    - Incremental backups: Only changes since last backup.
    - Differential backups: Changes since the last full backup.
    - Snapshots: Instantaneous state of the system at a specific point in time.
    - Replication: Real-time synchronization across multiple locations.
- **Backup Media**:
    - Tapes
    - Hard drives
    - Cloud storage
    - Optical media
- **Storage Location**:
    - Onsite: Same physical location as the original data.
    - Offsite: Different physical location, often used for disaster recovery.
- **Backup and Recovery Software**: Third-party tools or OS built-in features.

## Onsite vs. Offsite Backups

### Onsite Backups
- **Definition**: Backup data is stored at the same physical location as the original data.
- **Advantages**:
    - No Internet/WAN link required for backup or recovery.
    - Data immediately available for restoration.
    - Generally less expensive.
- **Disadvantages**:
    - Vulnerable to local disasters (fire, flood, theft).
    - Limited geographic redundancy.

### Offsite Backups
- **Definition**: Backup data is stored at a different physical location from the original data.
- **Methods**:
    - Cloud storage or remote data center via Internet/WAN link.
    - Physically transporting backup media to a third-party site.
- **Advantages**:
    - Data available after primary site disaster.
    - Restoration possible from anywhere (if network-connected).
    - Geographic redundancy.
- **Disadvantages**:
    - Requires Internet/WAN for data transfer, which can be slow and costly.
    - Backup media may not be immediately accessible.
    - Generally more expensive due to service fees or transport costs.

### Common Practice
- Organizations often use both onsite and offsite backups. Onsite backups are quick for frequent recoveries; offsite backups provide long-term disaster recovery options.

## Frequency
- **How Often to Backup**: Determined by data criticality and change frequency.
    - Weekly, daily, hourly?
- **System-dependent**:
    - Static systems (e.g., configuration servers) may require weekly backups.
    - Highly transactional systems (databases, user files) need frequent backups (daily, hourly).
- **Multiple Backup Sets**: Different frequencies for different data sets or types of backups:
    - Daily: Capture daily changes.
    - Weekly: Full backups.
    - Monthly: Archival purposes.

## Encryption
- **Security Concerns**: Sensitive data on backup media is at risk if accessed by unauthorized parties, especially offsite or in transit.
    - Example: Backup tapes stolen from an employee's vehicle.
- **Solution**: Encrypt backup data to protect against theft and unauthorized access.
    - Everything becomes unreadable without the correct recovery key.
    - Loss of this key results in permanent data loss.

## Snapshots
- **Popularity**: Popular for virtual machines (VMs) and cloud environments.
- **Concept**: Take an instant snapshot of a system at a specific point in time, capturing its current configuration and state.
- **Mechanism**:
    - First snapshot is a full copy.
    - Subsequent snapshots capture only changes since the last snapshot.
- **Advantages**:
    - Very fast recovery: Quick rollback to any previous snapshot.
    - Useful for testing changes before applying them.

## Recovery Testing
- **Crucial Principle**: Ensure backups can be restored effectively.
- **Purpose**: Verify that backups are viable and the recovery process works as expected.
- **Methods**:
    - Disaster recovery testing: Simulate a disaster scenario (e.g., server failure, data corruption) and attempt to restore from backup.
    - Confirm restoration functionality after restoring application and data.

## Replication
- **Definition**: An ongoing, real-time backup process that keeps data synchronized across multiple locations.
- **Advantages**:
    - High availability: Data always available; replication ensures continuous access.
    - Low RTO (Recovery Time Objective): Quick failover to the replicated site in case of primary site failure.
    - Low RPO (Recovery Point Objective): Minimal data loss due to near real-time synchronization.
- **Use Cases**:
    - Disaster recovery: Quickly switch over to a replicated site if the primary location fails.
    - High-volume, critical applications where downtime or data loss is unacceptable.

## Journaling
- **Problem Addressed**: Prevents data corruption due to unexpected system crashes during write operations.
- **Solution**: Implement journaling file systems or application-level journaling.
- **Mechanism**:
    1. **Journal Entry Before Write**: Record the intended change in a special log (journal).
    2. **Data Write Followed by Journal Update**: Write data to storage, then update the journal entry for completion.
- **Recovery Process with Journaling**: Ensures data consistency upon unexpected shutdowns, reducing corruption and simplifying recovery.

## Takeaways for Exam Prep

1. **Backups are Foundational**: Understanding backups is crucial for business continuity and data integrity. They are not a "nice-to-have" but a critical component of any IT strategy.
2. **Comprehensive Planning is Key**: Consider factors like data volume, criticality, type of backup, storage location, media, software, and frequency in your planning.
3. **Onsite vs. Offsite**:
    - **Onsite Backups**: Fast, cheap for quick local recovery.
    - **Offsite Backups**: Essential for disaster recovery, providing geographical redundancy. Often used together with onsite backups for a layered approach.
4. **Encryption is Non-Negotiable for Sensitive Data**: Encrypt backup data to protect against theft and unauthorized access, especially for offsite and cloud backups.
5. **Snapshots for Speed and Virtual Environments**: Snapshots are instant, point-in-time copies, useful for VMs and cloud environments. They store only changes after the initial full copy.
6. **Recovery Testing is Paramount**: Regularly test recovery processes to ensure data can be restored effectively and applications function correctly post-restoration.
7. **Replication for Near Real-Time Availability**: Use replication for critical systems requiring minimal downtime or data loss, providing high availability and low RTO/RPO.
8. **Journaling for Data Integrity During Writes**: Journaling prevents data corruption during unexpected system crashes by logging transactions before committing them to storage, ensuring data consistency upon restart.
