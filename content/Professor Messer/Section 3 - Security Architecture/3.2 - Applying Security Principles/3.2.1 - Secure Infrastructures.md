# Secure Infrastructures

## Device Placement

### General Principles
- Each network is unique, but many share common security approaches.
- Network design depends on the organization's goals (e.g., manufacturing vs. medical environments).
- Despite differences, core security components and patterns remain consistent.

### Key Devices and Their Placement
- **Firewalls:**
  - **Purpose:** Separate trusted networks from untrusted ones.
  - **Function:** Provide additional security checks by controlling traffic flow based on predefined rules.
  - **Goal:** Keep attackers outside the network while allowing legitimate traffic to pass through.
  - **Placement:** Typically at network boundaries (e.g., between internal and internet) and within internal segments to create zones.

- **Other Security Technologies:**
  - **Honeypots:** Decoy systems designed to attract and trap attackers. Placed in ways that make them seem vulnerable but isolated from critical assets.
  - **Jump Servers:** Hardened, secure servers used as intermediaries for accessing other devices in different security zones. Reduce direct exposure of sensitive systems.
  - **Load Balancers:** Distribute network traffic across multiple servers to improve performance and reliability. Offer security features like DDoS protection and SSL offloading. Placed in front of server farms.
  - **Sensors:** Devices like Intrusion Detection Systems (IDS) or Intrusion Prevention Systems (IPS) that monitor for malicious activity. Placed at strategic points in the network.

## Security Zones

### Concept of Security Zones
- **Definition:** Logical segmentation based on device use or access type, rather than physical location.
- **Purpose:** Allow better control over security policies and reduce the risk of a breach spreading.

### Examples of Security Zones
- **Basic Zones:**
  - **Trusted:** Internal networks considered safe.
  - **Untrusted:** External networks like the internet.
  
- **More Granular Zones:**
  - **Internal:** General user workstations and internal applications.
  - **External:** Public-facing internet.
  - **Servers:** Dedicated segments for application servers.
  - **Databases:** Highly sensitive data storage with strict access controls.
  - **Screened (DMZ):** Buffer zone between internal network and the internet, hosting public services while isolating them from the main network.

### Benefits of Security Zones
- **Simplifies Security Policies:** Easier to write, understand, implement, and maintain policies based on zones rather than individual IP addresses.
  - **Examples:**
    - **Trusted to Untrusted:** Internal users can access the internet.
    - **Untrusted to Screened:** External users can access public services in the DMZ.
    - **Untrusted to Trusted:** Generally restricted, with only specific and highly controlled traffic allowed (e.g., via a VPN).
- **Improved Security:** Limiting the spread of attacks by segmenting the network into zones.
- **Granularity:** Tailored security rules for each zone.

## Attack Surface

### Understanding Attack Surface
- **Analogy:** "How many ways can an attacker enter your home?" (doors, windows, basements). In a network, these are potential entry points for unauthorized users.
- **Definition:** The sum of all possible points where an attacker can try to enter or extract data from the environment.
- **Nature of Vulnerabilities:** Everything connected to or involved in network operations can be a vulnerability.

### Common Vulnerabilities that Contribute to Attack Surface
- **Application Code:** Bugs, insecure coding practices, unpatched software vulnerabilities.
- **Open Ports:** Unnecessary services running on servers or devices providing potential entry points.
- **Authentication Process:** Weak passwords, lack of multi-factor authentication, exploitable flows.
- **Human Error:** Misconfigurations (e.g., firewall rules), social engineering, user inattention.

### Minimizing the Attack Surface
- **Goal:** Reduce possible entry points and vulnerabilities.
- **Methods:**
  - **Audit Code:** Regularly review application code for security flaws before deployment.
  - **Block Unnecessary Ports on Firewall:** Implement a "least privilege" approach, closing ports not essential for business operations.
  - **Monitor Network Traffic in Real-Time:** Use tools like IDS/IPS and SIEM (Security Information and Event Management) to detect and respond quickly to anomalies.

## Connectivity

### Security and Network Connections
- **Principle:** Every aspect of connectivity contributes to overall security.
- **Importance:** Attackers might attempt to tap into network connections to intercept data.

### Securing Network Cabling
- **Physical Security:** Protect the physical infrastructure of the network.
  - **Methods:**
    - **Protect Physical Drops:** Secure network jacks in desks, conference rooms, and other accessible areas to prevent unauthorized physical connections.
    - **Secure Cable Runs:** Protect cables between different parts of the building by placing them in conduits, locked closets, or physically secured locations.

### Encryption for Connectivity
- **Application-Level Encryption:**
  - **Purpose:** Encrypts data at the application layer before sending over the network.
  - **Benefit:** If an attacker taps into the network and captures packets, the data remains encrypted and unintelligible.
  - **Example:** HTTPS (Hypertext Transfer Protocol Secure) for web traffic.
  - **Note:** Often, "the hard work has already been done" as encryption is built into many modern applications.

- **Network-Level Encryption:**
  - **Purpose:** Encrypts entire network segments or connections for secure communication over untrusted networks.
  - **Use Cases:** Remote sites, off-site connections, connecting branch offices to a central data center.
  - **Examples:**
    - **IPsec Tunnels:** Used to create secure site-to-site VPN connections between two networks.
    - **VPN Connections:** Allow individual remote users to securely connect to a corporate network over the internet.

### Key Takeaways for Exams
- **Firewall Placement:** Understand its role in segmenting networks and enforcing policies between trusted and untrusted areas.
- **Security Zones:** Logical segmentation that simplifies policy creation. Be able to name different types of zones (e.g., Trusted, Untrusted, Screened/DMZ) and explain their purpose.
- **Attack Surface:** Encompasses all potential entry points. Minimizing it involves proactive measures like code audits, blocking unnecessary ports, and active monitoring for anomalies.
- **Connectivity Security:** Physical and logical security are crucial. Don't overlook physical cable protection.
- **Encryption Layers:** Differentiate between application-level (e.g., HTTPS) and network-level (e.g., VPNs, IPsec) encryption and understand their respective use cases.
