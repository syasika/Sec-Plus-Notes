# Intrusion Prevention Systems (IPS)

## Introduction to Intrusion Prevention System (IPS)

- **Definition**: An [Intrusion Prevention System (IPS)] is a network security device that monitors network traffic in real-time.
- **Primary Function**: To actively block or prevent identified malicious traffic or exploits from entering the network.
- **Action**: When a threat is detected, the IPS takes immediate action to stop it.

## Types of Intrusions IPS Addresses

IPS systems are designed to detect and prevent various forms of attacks and vulnerabilities, including:

- **Exploits against Operating Systems**: Attacks targeting known weaknesses in OS software.
- **Exploits against Applications**: Attacks targeting vulnerabilities in specific software applications.
- **Buffer Overflows**: A common vulnerability where a program attempts to write data beyond the allocated buffer, potentially leading to arbitrary code execution.
- **Cross-Site Scripting (XSS)**: Web security vulnerability that enables attackers to inject client-side scripts into web pages viewed by other users.
- **SQL Injection**: A technique used to attack data-driven applications, in which malicious SQL statements are inserted into an entry field for execution.
- **Other Vulnerabilities**: Any other known or suspected malicious patterns in network traffic.

## Intrusion Detection System (IDS) vs. Intrusion Prevention System (IPS)

Understanding the difference is crucial for your exam!

- **Intrusion Detection System (IDS)**:
  - **Function**: Primarily for detection and alerting.
  - **Action**: Monitors traffic and generates an alarm or alert when a potential intrusion is identified.
  - **Limitation**: It cannot block or prevent the traffic from reaching its destination. It only notifies.

- **Intrusion Prevention System (IPS)**:
  - **Function**: For prevention and blocking.
  - **Action**: Monitors traffic, identifies intrusions, and stops the malicious traffic before it gets into the network.
  - **Benefit**: Actively protects the network by preventing successful attacks.

## Failure Modes of In-Line Security Devices

Security devices like IPSs that sit "in-line" (meaning all traffic must pass through them) introduce a potential single point of failure. How the device behaves upon failure is crucial:

- **Hope for 100% Uptime**: Not realistic; eventually, something will break (power, hardware, software bug/crash).
- **Fail-Open**:
  - **Behavior**: When the system fails (e.g., loses power, crashes), data continues to flow through the device.
  - **Implication**: Network connectivity is maintained, but no security processing (inspection or blocking) occurs. The network becomes vulnerable.
  - **Priority**: Favors availability over security during failure.

- **Fail-Closed**:
  - **Behavior**: When the system fails, data does not flow through the device.
  - **Implication**: The network connection is severed, leading to downtime. However, no malicious traffic can pass through either.
  - **Priority**: Favors security over availability during failure.

- **Decision**: The choice between fail-open and fail-closed depends on the organization's specific security policies and tolerance for downtime vs. risk. Always check the device documentation.

## Device Connection Types (Deployment Modes)

### Active Monitoring (Inline Deployment)

- **Description**: The security system (typically an IPS) is connected physically inline with the network traffic flow.
- **Traffic Flow**: All network traffic must pass through the IPS.
- **Action**:
  - The IPS examines traffic in real-time.
  - It makes decisions on whether traffic is legitimate or malicious.
  - Malicious traffic is immediately identified and blocked/dropped by the IPS itself. It does not proceed further into the network.
- **Common Use**: Intrusion Prevention Systems (IPS) are commonly deployed in active monitoring mode.
- **Advantages**: Real-time prevention of attacks.
- **Disadvantages/Concerns**:
  - Introduces a single point of failure (ties to [Fail Modes of In-Line Security Devices]).
  - Risk of false positives blocking legitimate traffic.

### Passive Monitoring (Out-of-Band Deployment)

- **Description**: The security system (typically an IDS) examines a copy of the network traffic, rather than sitting directly in the traffic path.
- **Traffic Flow**: Normal network traffic flows unimpeded. A duplicate copy is sent to the IDS.
- **Methods for copying traffic**:
  - **Port Mirror (SPAN)**: A feature on a network switch that sends a copy of traffic from one or more ports (or VLANs) to another port for monitoring.
  - **Network Tap**: A physical device inserted into a network cable to create a copy of the traffic.
- **Action**:
  - The IDS examines the copied traffic for intrusions.
  - It can identify and alert on malicious traffic.
  - **Limitation**: It has no way to block (prevent) the original malicious traffic, as it's only seeing a copy. The original traffic continues to its destination.

- **Common Use**: Intrusion Detection Systems (IDS) are commonly deployed in passive monitoring mode.
- **Advantages**:
  - No downtime to the network if the IDS fails.
  - No risk of blocking legitimate traffic (false positives don't affect live traffic).
- **Disadvantages**:
  - Cannot prevent attacks in real-time. Malicious traffic still reaches its target.
  - Requires additional configuration (SPAN/tap).

## Key Takeaways for Exam

1. **Core Distinction (IPS vs. IDS)**:
   - **IPS = Prevention**: Stops attacks in real-time by blocking malicious traffic.
   - **IDS = Detection**: Identifies attacks and alerts, but cannot block traffic.

2. **IPS Deployment (Active/Inline)**:
   - Sits directly in the path of network traffic (e.g., Internet -> Firewall -> **IPS** -> Core Switch).
   - All traffic must pass through it.
   - Allows for real-time blocking.

3. **IDS Deployment (Passive/Out-of-Band)**:
   - Receives a copy of network traffic (not directly in the path).
   - Uses methods like [Port Mirror (SPAN)] or [Network Tap].
   - Cannot block traffic, only detects and alerts.

4. **Failure Modes (Crucial for IPS)**:
   - **Fail-Open**: Device failure means traffic continues to flow but without security checks. Prioritizes uptime over security.
   - **Fail-Closed**: Device failure means traffic stops flowing. Priorities security over uptime (causes network outage).
   - Understand the trade-offs and when each might be preferred.

5. **Types of Intrusions**: Be familiar with examples like buffer overflows, XSS, and SQL injection as common targets for IPS/IDS.

6. **Real-time vs. Post-event**: IPS acts in real-time to prevent. IDS detects but the malicious traffic might have already reached its target, requiring post-event remediation.

7. **Performance Impact**: IPS can introduce latency due to deep packet inspection. IDS has less direct impact on network performance since it processes a copy.
