# Port Security

## Overview
- **Definition**: Security applied to individual network interfaces, such as ports on a switch or connections to a wireless access point (WAP).
- **Purpose**: To control and authenticate who or what connects to the network at the access layer.
- **Authentication Methods**:
    - Often involves a username and password.
    - Can include other authentication factors.

## Extensible Authentication Protocol (EAP)
- **Definition**: An authentication framework, not a specific protocol itself. It provides a structure for various authentication methods.
- **Extensibility**:
    - Based on RFC standards.
    - Manufacturers can develop their own EAP methods such as EAP-TLS, EAP-PEAP, and EAP-TTLS, allowing flexibility in how authentication is performed.
- **Integration**:
    - Most common integration is with IEEE 802.1X.
    - EAP works within the 802.1X framework to prevent access to the network until successful authentication.

## IEEE 802.1X (Port-based Network Access Control - NAC)
- **Definition**: An IEEE standard for Port-based Network Access Control (NAC). Often simply referred to as NAC.
- **Core Function**: Ensures that a client device or user does not gain network access until it has successfully authenticated, even blocking basic functions like obtaining an IP address via DHCP.

### Components of IEEE 802.1X and EAP
1. **Supplicant**:
    - The client device (e.g., laptop, smartphone) attempting to gain network access.
2. **Authenticator**:
    - The network device that provides access and controls the port (examples: network switch, Wireless Access Point).
    - Acts as an intermediary between the Supplicant and the Authentication Server.
3. **Authentication Server**:
    - A backend server that validates the client's credentials.
    - Contains the user/device authentication database.

### Authentication Flow (Step-by-Step)
1. **Initialization**:
    - The Supplicant connects to the Authenticator (e.g., plugs into a switch port, attempts to connect to a Wi-Fi SSID).
    - At this point, no communication is allowed to the rest of the network. The Authenticator holds the port in an unauthorized state.
2. **EAP-Request (Identity Request)**:
    - The Authenticator detects the new connection and sends an EAP-Request message (specifically, an EAP-Request/Identity) to the Supplicant, asking for its identity.
3. **EAP-Response (Identity Response)**:
    - The Supplicant replies with an EAP-Response message (EAP-Response/Identity), providing its identity (e.g., a username).
4. **Authenticator Forwards Identity**:
    - The Authenticator forwards the Supplicant's identity to the Authentication Server.
5. **Authentication Server Challenge**:
    - The Authentication Server sends an EAP message back to the Authenticator, containing a challenge or request for additional credentials (e.g., password).
6. **Authenticator Forwards Challenge**:
    - The Authenticator forwards this challenge to the Supplicant.
7. **Supplicant Provides Credentials**:
    - The Supplicant responds with the requested credentials (e.g., password, certificate information).
8. **Authenticator Forwards Credentials**:
    - The Authenticator forwards these credentials to the Authentication Server.
9. **Authentication Server Validation**:
    - The Authentication Server validates the provided credentials against its database.
10. **Authentication Decision**:
    - If credentials match, the Authentication Server sends an EAP "Success" message to the Authenticator.
    - If credentials do not match, an EAP "Failure" message is sent.
11. **Network Access Granted/Denied**:
    - Upon receiving "Success," the Authenticator changes the port state to authorized, allowing full network access.
    - Upon receiving "Failure," the Authenticator keeps the port unauthorized, denying network access.

## Exam Takeaways
- **Core Concept of Port Security**: Understand that it's about securing access at the edge of the network (switch ports, WAPs) by verifying identity before any network communication can occur.
- **EAP vs. 802.1X**:
    - EAP is the framework for authentication methods (how you prove who you are).
    - 802.1X is the standard that uses EAP to control network access (when you can access the network).
    - They work together: 802.1X relies on EAP to perform the actual authentication exchange.
- **Function of 802.1X (NAC)**: Crucially, it prevents any network access until successful authentication. This is a key security feature to prevent unauthorized devices from even getting an IP address.
- **Three Key Components and Their Roles**:
    - Supplicant: The client trying to connect.
    - Authenticator: The network device the supplicant connects to, acting as an intermediary.
    - Authentication Server: The backend system (e.g., RADIUS, LDAP, TACACS+, Kerberos) that verifies the supplicant's credentials.
- **Understand the Authentication Flow**: Be able to describe the sequence of messages and actions between the Supplicant, Authenticator, and Authentication Server from initial connection to access granted or denied. Pay attention to EAP-Request/EAP-Response exchanges and when credentials are sent to the authentication server.
- **Common Authentication Databases**: Be familiar with RADIUS, LDAP, TACACS+, and Kerberos as examples of backend systems that can store and validate user/device credentials for 802.1X.
