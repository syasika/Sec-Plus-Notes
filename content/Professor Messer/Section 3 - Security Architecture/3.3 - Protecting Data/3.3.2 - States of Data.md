# States of Data

## Introduction
Data exists in different states, each with unique security considerations. Understanding these states is crucial for implementing effective data protection strategies.

## 1. Data at Rest
- **Definition**: Refers to data stored on a storage device.
- **Examples**: Hard drives (HDD), Solid State Drives (SSD), flash drives, databases, file servers, cloud storage.
- **Characteristics**:
    - It is static and not actively being processed or transmitted.
    - Even if not encrypted, it still falls under "data at rest."
- **Security Protections**:
    - **Encryption**: Essential for protecting data in case of unauthorized access to the storage device.
        - **Whole Disk Encryption**: Encrypts everything on the storage device (e.g., BitLocker, FileVault).
        - **Database Encryption**: Encrypts specific data within a database.
        - **File- or Folder-Level Encryption**: Encrypts individual files or entire folders (e.g., EFS on Windows).
    - **Permissions**: Controls who can access the data.
        - **Access Control Lists (ACLs)**: Assigns specific rights to users or groups (e.g., read, write, execute).
        - **Limits Access**: Ensures that only authorized users have access.

## 2. Data in Transit
- **Definition**: Refers to data being transmitted over a network.
- Also known as **data in motion**.
- **Examples**: Email, web traffic, file transfers, VPN traffic.
- **Characteristics**:
    - Actively moving between devices (e.g., computer to server, server to server).
    - Traverses many intermediate devices: switches, routers, firewalls, etc.
    - Vulnerable to eavesdropping or interception without proper protection.
- **Security Protections**:
    - **Network-based Protection**:
        - **Firewalls**: Filter traffic based on rules (ports, protocols, IP addresses).
        - **Intrusion Prevention Systems (IPS)**: Detect and prevent malicious network activity.
    - **Transport Encryption**:
        - **TLS (Transport Layer Security)**: Used for encrypting web traffic (HTTPS) and other application-layer data.
        - **IPsec (Internet Protocol Security)**: Encrypts entire IP packets, often used for Virtual Private Networks (VPNs) to secure all network traffic between two points (site-to-site VPNs or remote access VPNs).

## 3. Data in Use
- **Definition**: Refers to data actively being processed in memory by a computer system.
- **Examples**: Data in System RAM, CPU registers, CPU cache.
- **Characteristics**:
    - Must be decrypted to process (you can't work with encrypted data directly).
    - Highly vulnerable while in this state.
- **Security Implications/Risks**:
    - **Attacks Targeting RAM**: Attackers can extract decrypted information directly from memory. This is a highly attractive option for adversaries.
    - **Real-world Example: Target Corp. Breach (November 2013)**:
        - **Details**: Malware installed on Point-of-Sale (POS) terminals.
        - **Exploitation**: Scraped credit card numbers from RAM after they were decrypted for processing but before re-encryption.
        - **Outcome**: Theft of 110 million credit card numbers.
    - **Target's Security Flaw**: Despite having data-in-transit and data-at-rest encryption, the vulnerability was in the "data in use" state.

- **Security Protections**:
    - Traditional encryption is challenging to apply here.
    - Focus shifts to **system integrity and access control** to prevent unauthorized memory access.
    - Implement measures like **secure boot**, **memory encryption features (e.g., Intel SGX, AMD SEV)**, strong authentication, and endpoint detection and response (EDR).

## 4. Data Sovereignty
- **Definition**: Refers to the principle that data residing in a country is subject to the laws of that country.
- **Characteristics**:
    - Impacts legal monitoring, court orders, data retention, and data transfer rules.
    - Organizational considerations when operating internationally.
- **Key Regulation Example: GDPR (General Data Protection Regulation)**:
    - Dictates that data collected on EU citizens must be stored within the EU.
    - Complex interplay of technology and legal compliance.

## 5. Geolocation
- **Definition**: The process of determining real-world geographic location.
- **Methods to Determine Location**:
    - **802.11 (Wi-Fi)**: Based on Wi-Fi access point signals.
    - **Mobile Providers**: Cell tower triangulation.
    - **GPS (Global Positioning System)**: Satellite-based positioning.
- **Use Cases for Data Access Management**:
    - **Prevent Access from Other Countries**: Media streaming services use geolocation to enforce regional licensing agreements.
    - **Limit Administrative Tasks**: Enhanced security protocols for critical operations when a user is outside a trusted physical location.
    - **Grant Enhanced Privileges**: More access granted in corporate offices compared to remote work.

## Takeaways for Exam Preparation

1. **Memorize the Three States of Data**:
    - **Data at Rest**: Stored data.
    - **Data in Transit**: Moving data across networks.
    - **Data in Use**: Actively processed data in memory.
    - Be able to define each and provide examples.

2. **Understand Primary Security Concerns for Each State**:
    - **Data at Rest**: Unauthorized access to storage devices, physical theft.
    - **Data in Transit**: Eavesdropping, interception, man-in-the-middle attacks.
    - **Data in Use**: Memory scraping (data is decrypted here), unauthorized access to running processes. Often considered the most vulnerable state.

3. **Know Key Mitigation Strategies for Each State**:
    - **Data at Rest**:
        - **Encryption**: Whole disk, database, file/folder level.
        - **Permissions**: Access Control Lists (ACLs) for users and groups.
    - **Data in Transit**:
        - **Network Protection**: Firewalls, Intrusion Prevention Systems (IPS).
        - **Transport Encryption**: TLS (web servers), IPsec (VPNs).
    - **Data in Use**:
        - Focus on **system security** and **access control** to the system itself.
        - Secure boot, memory protection features, strong authentication, endpoint security solutions.

4. **Recall Key Examples**:
    - **Target Breach (2013)**: A prime example of data-in-use exploitation where credit card numbers were scraped from POS terminal RAM despite other encryption being in place.

5. **Define and Understand Data Sovereignty**:
    - **Definition**: Data is subject to the laws of the country where it resides.
    - **Importance**: Legal compliance, international data transfer regulations.
    - **Example**: GDPR requiring EU citizen data to be stored within the EU.

6. **Understand Geolocation and its Security Applications**:
    - **Methods**: 802.11 (Wi-Fi), mobile providers, GPS.
    - **Security Use**: Managing data access based on location (e.g., restricting access from certain countries, granting enhanced privileges within a corporate building).

7. **Think About the "Why"**: For each state and protection, ask yourself why it's needed and how it works. This deeper understanding will help you answer scenario-based questions.
