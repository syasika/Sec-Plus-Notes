# Protecting Data

## Geographic Restrictions

### Definition
Geographic restrictions are policy decisions based on where data is located or the user's location.

### Network Location
- **IP Subnet Identification**: Users and devices can be identified based on their IP subnet, which works well for internal private networks.
- **Mobile Devices**: More challenging due to changing or less precise IP addresses.

### Geolocation
- **GPS (Global Positioning System)**: Provides very accurate location data for mobile devices.
- **Wi-Fi**: Less accurate than GPS but can be used with databases of known Wi-Fi SSIDs and their locations.
- **IP Address**: Not very accurate, especially with mobile devices or when using a Virtual Private Network (VPN).

### Geofencing
- **Definition**: Automatically allow or restrict access to data/applications based on geographic location (virtual fence).
- **Policy Application**: Policies are associated with specific locations determined by network location or geolocation.
- **Example**: An app only runs if you are near the office.

## Protecting Data: General Principles

### Primary Job Task
Protecting data is a fundamental responsibility for IT professionals. Without proper data protection, an organization risks losing its business operations and critical information.

### Data Locations
- **Storage Drives**: Laptops, mobile devices.
- **Network**: Traversing private or public internet.
- **CPU/Memory**: Data being actively processed.
- **Attack Vectors**: Proper data protection is needed regardless of the location of the data.

### Methods of Protection
- **Encryption**
- **Security Policies**
- **Data Permissions**

## Encryption

### Definition
Encryption converts information into unreadable data (ciphertext) to ensure confidentiality. The reverse process, decryption, requires a proper key.

### Properties
- **Confusion**: Even small changes in plaintext result in significantly different ciphertext.
- **Example**: "Hello, World!" encrypted with PGP produces a block of seemingly random characters.

## Hashing

### Definition
Hashing represents data as a fixed-length string (message digest or fingerprint) to ensure integrity and confidentiality.

### Properties
- **One-Way Trip**: It is computationally impossible to recover the original message from the hash digest.
- **Uses**:
  - **Storing Passwords**: Hashed before storage; comparing hashes instead of actual passwords.
  - **Document Integrity**: Confirming that a downloaded file matches its original form.
  - **Digital Signatures**: Combining hashing with public-key cryptography to ensure authentication, non-repudiation, and integrity.

### Example (SHA256)
- "My name is Professor Messer" → `d41d8cd98f00b204e9800998ecf8427e`
- Changing the text results in a completely different hash value, ensuring data integrity.

## Obfuscation

### Definition
Obfuscation makes information or code hard to understand but does not mathematically hide it like encryption.

### Purpose
Protects sensitive information and prevents malicious intent from being easily understood.

### Examples
- **Complex Script**: A simple script transformed into a long, complex, unreadable yet functionally identical version.
- **Credit Card Numbers on Receipts**: Showing only the last four digits with asterisks (e.g., `************2512`).

## Masking

### Definition
Masking hides sensitive data by substituting it with generic placeholders.

### Purpose
Protects Personally Identifiable Information (PII) and other sensitive data while keeping full data intact for authorized personnel or processes.

### Techniques
- **Substitution**: Replacing parts of the data.
- **Shuffling**: Rearranging characters in a masked way.
- **Encryption Parts**: Encrypting specific portions of data.
- **Example**: Credit card number shown as `************2512` on a receipt, with full details stored separately.

## Tokenization

### Definition
Tokenization replaces sensitive data with non-sensitive placeholders (tokens).

### Mechanism
A secure system generates unique tokens for pieces of sensitive data. These tokens are used in transactions or storage, while the original data is securely stored elsewhere.

### Common Usage: Credit Card Processing
- **Process**:
  1. User registers a credit card with a mobile payment app.
  2. Card details sent to Remote Token Service Server.
  3. Server provides tokens back to the device.
  4. During payment, phone sends a token via NFC to the Merchant Payment Processing Server.
  5. The Merchant Server sends the token to the Remote Token Service Server for validation.
  6. Validation approves the transaction without revealing the actual credit card number.

## Segmentation

### Definition
Segmentation separates data into smaller, distinct pieces and stores them in different locations.

### Problem with Single Data Source
- **Single Large Database**: One breach can expose all customer data easily.
- **Solution**: Separate sensitive data types (names, addresses, financial details) across multiple databases or locations.

### Layered Security
- **Granular Control**: Stronger security measures applied to highly sensitive data (e.g., healthcare info, financial details).
- **Example**: Less sensitive data (e.g., names) might have minimal security; more sensitive data would have stronger controls.

## Permission Restrictions

### Definition
Permission restrictions control access based on defined policies after successful authentication.

### Authentication Process
- **Password Policies**: Rules for password complexity, length, rotation.
- **Authentication Factor Policies**: Requirements for multi-factor authentication (MFA).
- **Other Considerations**: Account lockout policies, brute-force protection.

### Permissions After Login
- **Another Line of Defense**: Prevents unauthorized access to specific resources.
- **Example**: Users assigned to groups with specific file/folder permissions (read, write, execute).

## Exam-Focused Takeaways

1. **Geographic Restrictions vs. Geolocation vs. Geofencing**
   - **Geographic Restrictions**: Broad policy decisions based on location.
   - **Geolocation**: Determining precise locations (most accurate: GPS, then Wi-Fi, then IP).
   - **Geofencing**: Applying rules based on geolocation (e.g., app only works in a specific area).

2. **Fundamental Importance of Data Protection**
   - Data is everywhere and critical for business continuity.

3. **Encryption vs. Hashing**
   - **Encryption**: Two-way process, requires a key, provides confidentiality.
   - **Hashing**: One-way process, impossible to reverse, provides integrity and confidentiality (by not revealing original data).
   - **Confusion**: Both encryption and hashing make output drastically different from input.

4. **Obfuscation as a Deterrent**
   - Makes data/code hard to understand but doesn’t mathematically hide it like encryption.
   - Used for code protection or hiding malicious intent.

5. **Masking vs. Tokenization**
   - **Obfuscation**: General concept of making something unclear.
   - **Masking**: Hiding parts of sensitive data (e.g., asterisks on a credit card number).
   - **Tokenization**: Replaces sensitive data with non-sensitive placeholders, mathematically unrelated to the original data.

6. **Benefits of Data Segmentation**
   - Reduces impact of a single breach.
   - Allows for granular security measures applied to more sensitive data segments.

7. **Key Components of Permission Restrictions**
   - Beyond just username/password.
   - Includes robust authentication policies (password complexity, MFA) and authorization policies (groups, file permissions).
