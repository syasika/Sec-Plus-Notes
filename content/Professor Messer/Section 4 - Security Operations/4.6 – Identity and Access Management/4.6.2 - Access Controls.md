# Access Controls

## Introduction to Access Control

### Authorization: Granting Specific Permissions
- **Authorization**: The process of ensuring only authorized individuals can access resources.
  - **Policy Enforcement**: Implementing rules that allow or disallow access.
  - **Policy Definition**: Determining what rights an individual should have.

Access control can be associated with both **individuals** and **groups**. IT teams translate policy definitions into operating system (OS) processes, ensuring users receive the necessary rights to meet business needs or mission requirements.

## Least Privilege

### Security Best Practice
- **Definition**: Rights and permissions are set to the bare minimum required for a user to complete their objective.
  - You only get exactly what's needed for your job function.
  - No additional rights or administrator access by default.

### Implementation
- **Limiting User Accounts**: All accounts must be limited in privileges.
- **Running Applications with Minimal Privileges**: Ensure applications run with minimal permissions.
- **Avoid Administrative Privileges**: Do not allow users to run with administrative privileges.

### Benefits
- Limits the scope of malicious behavior. If malware runs, it's confined to the user’s limited permissions, reducing potential damage.

## Mandatory Access Control (MAC)

### High Security Environments
- **Definition**: The operating system strictly limits operations on an object based on security clearance levels.
  - Every object gets a label: e.g., Confidential, Secret, Top Secret.
  - Labeling uses predefined rules set by the administrator.
  - Users cannot change these settings.

### Control Mechanism
- The administrator defines rights and permissions for users based on their clearance level and the object's label. For example:
  - Shipping department user has access to "Confidential" data, while a manager has access to "Top Secret" data.

### Security Benefits
- Very strong and highly structured, making it suitable for environments requiring high security.

## Discretionary Access Control (DAC)

### Common in Most Operating Systems
- **Definition**: The owner (creator) of the data controls who has access and how.
  - If you create a spreadsheet, you control who can access it.
  - You can modify access at any time (e.g., read-only, modify).

### Security Considerations
- **Flexibility**: Very flexible but also very weak due to reliance on individual users setting appropriate security controls.

## Role-based Access Control (RBAC)

### Centralized Control Model
- **Definition**: Access is based on the user's role in the organization.
  - Examples of roles: Manager, Director, Team Lead, Project Manager.

### Implementation
- **Administrators** create different groups and assign rights/permissions to the group itself.
- **Users are then added to these groups**, implicitly gaining the associated rights and permissions.
- Rights are gained implicitly instead of explicitly.

### Windows Example
- In a "Shipping and Receiving" group, users can use shipping software.
- In a "Manager" group, users can review shipping logs.

### Benefits
- Simplifies management of permissions in larger organizations.

## Rule-based Access Control

### Generic Term for Following Rules
- **Definition**: Access is determined through system-enforced rules (conditions other than who you are or your role).
  - The rule is created by the administrator and associated with the object. The system checks ACLs for that object.

### Examples of Rules
- Lab network access is only available between 9 AM and 5 PM.
- Only Chrome browsers may complete this web form.

### Flexibility
- Allows administrators to set specific criteria for access, providing a flexible control mechanism.

## Attribute-based Access Control (ABAC)

### Modern "Next Generation" Authorization Model
- **Definition**: Users can have complex relationships with applications and data, and access is based on many different criteria.
  - The system considers various parameters dynamically and evaluates multiple attributes simultaneously.

### Characteristics
- **Aware of Context**: Considers various parameters like resource sensitivity, IP address, time of day, desired action, user attributes, and environment attributes.
- **Granular and Dynamic Rule Sets**: Administrators can create complex rule sets that are highly dynamic and context-aware.

### Security Benefits
- Allows administrators to create very complex, granular, and dynamic access control policies.

## Time-of-day Restrictions

### Access Control Option in Most Devices
- **Definition**: Restricts access during certain times or days of the week.
  - Usually combined with other models (e.g., rule-based access control might include time-of-day as a condition).

### Implementation Challenges
- Can be difficult to implement accurately, especially in global environments due to different time zones.

### Examples
- Training room network is inaccessible between midnight and 6 AM.
- Conference room access is limited after 8 PM.
- R&D databases are only available after 8 AM and between 6 PM.

## Key Terms

- **Authorization**: Granting specific permissions to access resources.
- **Least Privilege**: Granting only the minimum necessary permissions.
- **Mandatory Access Control (MAC)**: System-enforced, label-based access control.
- **Discretionary Access Control (DAC)**: Owner-based access control.
- **Role-based Access Control (RBAC)**: Access based on user's organizational role.
- **Rule-based Access Control**: Access based on system-enforced rules/conditions.
- **Attribute-based Access Control (ABAC)**: Dynamic access based on multiple attributes/criteria.
- **Time-of-day restrictions**: Limiting access to specific time periods.

## Exam Takeaways

1. **Core Concept of Access Control**:
   - Understand that it's about authorization – determining and enforcing who can access what resources, and how. It's distinct from authentication (proving who you are).

2. **Least Privilege is Paramount**:
   - Always apply the principle of least privilege.
   - Why? It's a fundamental security best practice that limits potential damage from compromised accounts or malicious software.
   - If asked about any access control model, consider how least privilege would apply.

3. **Differentiate Main Access Control Models (MAC, DAC, RBAC, Rule-based, ABAC)**:
   - **DAC (Discretionary Access Control)**:
     - Who controls? The owner (creator) of the resource.
     - Security? Weakest due to reliance on individual users.
     - Flexibility? Most flexible.
     - Use Case: Personal files on a workstation.
   - **MAC (Mandatory Access Control)**:
     - Who controls? The system administrator (or OS) enforces labels.
     - Security? Strongest/most rigid, used for high-security data.
     - Mechanism: Objects have sensitivity labels, users have clearance levels.
     - Use Case: Military, government classified data.
   - **RBAC (Role-based Access Control)**:
     - Who controls? Administrators assign permissions to roles; users are assigned to roles.
     - Mechanism: Users gain rights implicitly by being part of a group/role.
     - Benefit: Scalable and easier to manage in larger organizations than DAC.
     - Use Case: Common in enterprise environments (e.g., "HR Manager" role, "IT Support" role).
   - **Rule-based Access Control**:
     - Who controls? System administrators define rules.
     - Mechanism: Access granted/denied based on specific, predefined conditions related to the object (not necessarily the user's identity or role directly).
     - Use Case: Time-restricted access, specific browser requirements.
   - **ABAC (Attribute-based Access Control)**:
     - Who controls? Administrators define policies based on multiple attributes.
     - Mechanism: "Next-generation" dynamic model. Access is granted based on evaluation of multiple attributes (user, resource, environment, action).
     - Benefit: Highly granular and context-aware, very flexible for complex scenarios.
     - Use Case: Cloud environments, microservices, dynamic access needs.

4. **Time-of-Day Restrictions**:
   - Function: Limits access based on time and day.
   - Integration: Often used in conjunction with other access control models (e.g., an RBAC role might only have access during business hours).
   - Challenge: Implementing accurately in global, 24-hour environments due to time zones.

5. **Distinguish Between RBAC and Rule-based Access Control**:
   - RBAC focuses on who you are (your role/group).
   - Rule-based focuses on conditions other than who you are (e.g., time, location, device).
   - ABAC is essentially a highly advanced, dynamic form of rule-based access control that considers many attributes simultaneously, making it context-aware.

6. **Security vs. Flexibility Trade-offs**:
   - Understand that DAC offers high flexibility but low security.
   - MAC offers high security but low flexibility.
   - RBAC and ABAC aim to strike a balance, offering more centralized control and scalability while maintaining good security.
