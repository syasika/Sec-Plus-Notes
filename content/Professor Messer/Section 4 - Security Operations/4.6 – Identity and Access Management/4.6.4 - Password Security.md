# Password Security

## 1. Password Complexity and Length

### Goal of Strong Passwords
- **Resist guessing or brute-force attacks.**
- **Increase password entropy:** A measure of unpredictability.
  - Avoid single words (dictionary attacks).
  - Avoid obvious passwords like "password123."
  - Mix:
    - Uppercase letters
    - Lowercase letters
    - Numbers
    - Special characters

**Stronger passwords are typically at least 8 characters long.**
- Note: As attackers' systems become faster, longer passwords are always better.
- Consider a passphrase for enhanced complexity and easier remembering.

## 2. Password Age and Expiration

### Password Age
- **Definition:** The time elapsed since the last password change.
- **Purpose:** Ensures that passwords are periodically updated to reduce the risk of compromise.

### Password Expiration
- **Functionality:** Passwords expire after a certain period (e.g., 30, 60, or 90 days).
- **Impact:** Once expired, users must reset their password.
- **Password History:** Systems often keep track of previous passwords to prevent reusing old ones.
- **Critical Systems:** May require more frequent changes due to higher security needs.
- **Admin Control:** Policies are set by system administrators.

## 3. Password Managers

### The Problem
- Best practice: Use unique, strong passwords for each account.
- Reality: Humans find it impractical to remember complex, distinct passwords for every service.
- Risk of reuse: If one account is compromised, the attacker can access multiple accounts with the same credentials.

### The Solution: Password Managers
- **Function:** Store all passwords in a single, secure database.
- **Security Features:**
  - **Encrypted and protected:** Requires a master password or other authentication to access.
  - Can include multifactor tokens for extra security.
- **Benefits:**
  - Allows users to create unique, strong passwords for each service.
  - Many managers can generate new, random passwords automatically.
  - Provide password health checks (e.g., identifying reused, compromised, or weak passwords).
- **Availability:**
  - Built-in to many operating systems (e.g., macOS Keychain, Windows Credential Manager).
  - Built-in to some browsers (e.g., Chrome, Firefox).
  - Third-party applications (e.g., LastPass, 1Password, Bitwarden).
  - Enterprise password managers offer centralized management and recovery for organizations.

## 4. Passwordless Authentication

### The Motivation
- Many security breaches stem from poor password control (weak passwords, insecure implementation, password reuse).
- Passwords are a significant attack vector.

### The Concept
- **Authenticate without using a password:**
- **Benefit:** Removes the vulnerability of passwords by eliminating them entirely.

### Examples
- **Facial recognition:** Unlocking mobile phones or logging into systems using biometrics.
- **Security keys:** Physical tokens confirming user identity.
- **Personal Identification Numbers (PINs):** Used instead of complex passwords for device login (e.g., Windows Hello).

### Implementation
- Passwordless authentication may not always be the primary method but is often used in conjunction with a password or additional factors (e.g., initial setup with a password, then passwordless for daily login).

## 5. Just-in-Time (JIT) Permissions

### The Problem in Organizations
- IT teams are frequently given permanent administrator/root elevated account rights.
- These accounts are highly attractive to attackers due to their extensive privileges.

### The Solution: JIT Permissions
- **Grant admin access temporarily only:**
- **Core Principle:** Adheres to the principle of least privilege, meaning no permanent elevated rights.

**Benefits:**
- Narrows the scope of a breach. If a user account is compromised, its elevated rights will expire, limiting potential damage.

### How JIT Permissions Work
1. **Request Access:** A user (e.g., an IT technician) requests elevated permissions from a central clearinghouse.
2. **Policy Evaluation:** The clearinghouse grants or denies the request based on predefined security policies.
3. **Password Vaulting:**
    - Primary, highly privileged credentials are stored securely in a password vault.
    - Controls who gets access to these credentials.
4. **Temporary Accounts/Credentials:**
    - Temporary credentials (time-limited) are generated based on primary vaulted credentials.
    - The primary passwords are never directly released to the user.
    - Administrators receive these temporary credentials.
5. **Session-Based Usage:**
    - Credentials are used for one specific session or task.
    - Once the session is complete (or time limit expires), the credentials are deleted.

## Key Concepts for Exams
- **Password Entropy:** Understand how to increase it through length, complexity, and randomness.
- **Password Policies:** Differentiate between password age and expiration, and understand the role of password history.
- **Password Managers:** Know their purpose, key features (encryption, generation, health checks), and benefits (unique, strong passwords, multifactor integration).
- **Passwordless Authentication:** Understand its goal (eliminating password vulnerabilities), examples (biometrics, security keys, PINs), and how it addresses traditional password management issues.
- **Just-in-Time (JIT) Permissions:** This is a crucial concept. 
  - **Problem it solves:** Permanent elevated privileges for IT staff.
  - **Core principle:** Least Privilege.
  - **Mechanism:** Temporary, ephemeral credentials granted via a central clearinghouse and password vaulting. Primary passwords are never exposed.
  - **Benefit:** Significantly reduces the attack surface and impact of compromised privileged accounts.
