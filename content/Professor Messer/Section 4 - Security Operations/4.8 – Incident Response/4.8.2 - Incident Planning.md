# Incident Planning

## Overview
**Definition**: Refers to the preparation and execution of strategies to manage security incidents effectively.

### Key Components
- **Exercising**
- **Tabletop Exercises**
- **Simulations**
- **Root Cause Analysis (RCA)**
- **Threat Hunting**

---

## 1. Exercising

Exercising involves testing incident response plans before an actual event occurs, much like a fire drill for cybersecurity.

### Key Principles
- **Purpose**: To evaluate and improve response plans in a controlled environment.
- **Frequency**: Should be conducted regularly (e.g., annually or semi-annually) to maintain readiness.
- **Rules of Engagement (RoE)**: Must be clearly defined before any exercise begins, with the critical rule being that no production systems should be touched. Exercises must take place in sandboxed environments.
- **Scope & Constraints**: Exercises focus on specific scenarios and have time limits to accommodate all participants.

### Post-Exercise Evaluation
After an exercise:
- Document and discuss the response.
- Identify weaknesses and make necessary improvements for future incidents.

---

## 2. Tabletop Exercises

A tabletop exercise is a discussion-based session where team members walk through simulated incident scenarios, testing the logical flow of their incident response plans without physical actions.

### Characteristics
- **Cost-Effective**: Cheaper and faster than full-scale disaster drills.
- **Logistics & Analysis**: Focuses on analyzing the plan and determining logistical issues without performing actual tasks.
- **Process**:
    1. Gather key players (e.g., IT, security, legal, HR, management).
    2. Present a simulated scenario (e.g., "Our primary database has been encrypted by ransomware").
    3. Discuss the response plan step-by-step, identifying roles and responsibilities.

### Goal
To identify gaps or flaws in documented policies and procedures.

---

## 3. Simulation

A simulation involves actively testing security events to assess how both technology and human behavior respond.

### Key Aspects
- **Simulated Events**: Common scenarios include phishing attacks, password compromise requests, and data breach attempts.
- **Example: Phishing Simulation**
    - **Action**: The security team creates a realistic (but harmless) phishing email and sends it to the user community.
    - **Goal**: Determine which users are likely to click on links or provide credentials.
    - **Dual Testing Purpose**:
        1. Test internal security technology.
        2. Identify individuals who may need additional security awareness training.

---

## 4. Root Cause Analysis (RCA)

After an incident has been contained, a root cause analysis is performed to understand the fundamental reasons for its occurrence.

### Core Concepts
- **Objective**: To identify the underlying causes rather than just surface-level symptoms.
- **Process**:
    - Create conclusions backed by facts and evidence (e.g., log files, forensic data).
- **Important Considerations**:
    - **Avoid Tunnel Vision**: Look for multiple contributing factors, not just one root cause.
    - **Human Error**: Mistakes happen. The focus is on understanding why the mistake occurred to improve future processes or training.

---

## 5. Threat Hunting

Threat hunting involves actively searching for threats and vulnerabilities within a network before they can be exploited.

### Key Ideas
- **Proactive vs. Reactive**: Unlike standard security monitoring, which is reactive, threat hunting is proactive (assuming a breach has occurred and looking for it).
- **Cat and Mouse Game**: Attackers constantly change their strategies, so defenses must adapt.
- **Intelligence-Driven**: Threat hunters use intelligence, knowledge of attacker TTPs (Tactics, Techniques, and Procedures), and hypotheses to guide searches.

### Example Hypothesis
"An attacker could be using PowerShell to move laterally. Let's search all endpoint logs for anomalous PowerShell activity."

### Goals
- **Find the Attacker Before They Find You**: Identify undetected malware or vulnerabilities.
- Speed up the response time by using technology and automation to find and stop threats quickly.

---

## Key Takeaways / Exam Prep

- **Exercise Types**:
    - **Tabletop Exercises**: Discussion-based, testing plan logic.
    - **Simulations**: Action-based, testing technology and human reactions.
- **Safety First**: Never test on production systems. This is a crucial exam concept.
- **Feedback Loop**: Document findings, evaluate, improve, and repeat the cycle.
- **Proactive Security**: Threat hunting is about finding issues before they become full-blown incidents.
- **Multi-Layered Failures**: Remember that successful attacks often result from multiple failures (e.g., filter bypass + user click).
- **Human Element**: Simulations like phishing campaigns are vital for testing the "human firewall" and identifying training needs.
