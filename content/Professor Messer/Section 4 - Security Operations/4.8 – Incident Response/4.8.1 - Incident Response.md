# Incident Response

## Introduction to Security Incidents

Security incidents are unwanted security events that can disrupt operations, compromise data, or damage a company's reputation. They are a crucial part of a security administrator's role.

### Examples of Security Incidents:
- **User clicks email attachment & executes malware:** Malware communicates with external servers (e.g., ransomware).
- **DDoS attack:** WAN connection overwhelmed by a botnet.
- **Confidential information stolen:** Data exfiltrated, attackers demand money or threaten public release.
- **User installs peer-to-peer software:** Allows external access to internal servers.

Incidents can occur in any organization at any time, requiring constant preparedness.

## NIST SP800-61: Incident Handling Guide

The National Institute of Standards and Technology (NIST) Special Publication 800-61 Revision 2 provides a structured approach to managing security incidents through the incident response lifecycle:

### 1. Preparation
This phase involves proactive measures taken before an incident occurs to ensure readiness.

#### Communication Methods:
- **Up-to-date contact lists** for all relevant personnel (internal teams, external vendors, legal, PR, law enforcement).
- Ensure methods are redundant and accessible even if primary systems are compromised.

#### Incident Handling Hardware and Software ("Incident Go-Bag"):
- **Laptops with specialized forensic tools.**
- **Removable media** (USB drives, external hard drives) for data acquisition and backups.
- **Forensic software** for imaging drives, analyzing logs, etc.
- **Digital cameras/video recorders** for documenting physical evidence and scenes.

#### Incident Analysis Resources:
- Comprehensive documentation (server configurations, network diagrams, asset inventories).
- Security baselines for systems and networks (known good configurations to compare against).
- Critical file hash values (checksums) to verify file integrity.

#### Incident Mitigation Software:
- **Clean OS and application images** for rapid system restoration.

#### Policies Needed for Incident Handling:
- Clearly defined policies and procedures so everyone knows their roles during an incident.

### 2. Detection and Analysis
Detection is challenging due to:

#### Many Different Detection Sources:
Each source has varying levels of detail and perception, making it hard to identify legitimate threats from noise.

#### Large Volume of Attacks:
Constant incoming attacks (scripts, probes) make distinguishing between noise and actual incidents difficult.

#### Incidents Are Often Complex:
Requiring extensive knowledge to understand subtle indicators.

### 3. Isolation and Containment
Isolation is generally a bad idea because an incident can spread quickly. Here are some methods:

#### Sandboxes:
- An isolated operating system environment.
- Used to run malware and analyze the results without affecting production systems.
- **Clean out the sandbox when done** to prevent further contamination.

### 4. Recovery after an Incident
The goal is to get things back to normal by removing the bad while keeping the good:

#### Eradicate the Bug:
- **Remove malware** (or reimage the system entirely).
- Disable breached user accounts or those created by attackers.
- Fix vulnerabilities that allowed entry.

#### Recover the System:
- Restore from backups (known good state).
- Rebuild from scratch using clean installation media.
- Replace compromised files with verified originals.
- Tighten down the perimeter and internal security controls to prevent re-entry.

## Post-Incident Activity: Lessons Learned

Learn and improve by conducting a post-incident meeting:

#### Invite Everyone Affected:
Security, IT, legal, management, users should all be present. Facilitate open discussion and information sharing.

#### Conduct the Meeting as Soon as Possible:
Memories fade over time. Conduct the meeting soon after incident resolution to apply recommendations for future events.

## Training for an Incident

There is limited on-the-job training when a security event occurs. It's essential to train the team beforehand:

- **Initial response procedures.**
- **Investigation plans.**
- **Incident reporting protocols.**

This proactive approach saves money by mitigating the impact of large incidents.

## Takeaways for Exam Preparation

1. **Memorize the NIST SP800-61 Incident Response Lifecycle:**
   - **Preparation:** Proactive measures are essential.
   - **Detection & Analysis:** Recognize challenges and differentiate between precursors (warnings) and indicators (active threats).
   - **Containment, Eradication, and Recovery:** Focus on stopping the spread, eliminating the threat, and restoring systems to a trusted state.
   - **Post-incident Activity:** Emphasize continuous improvement through lessons learned meetings.

2. **Understand the Importance of Each Phase:**
   - **Preparation:** Proactive measures are crucial. Know key elements like communication plans, incident go-bags, analysis resources, mitigation software, and clear policies.
   - **Detection & Analysis:** Recognize challenges and common detection sources (logs, IDS/IPS, antivirus, host-based monitors, network traffic).
   - **Containment, Eradication, and Recovery:** Focus on techniques like sandboxing (and its limitations), malware removal, account disabling, vulnerability patching, and restoring from backups/rebuilding.
   - **Post-Incident Activity:** Emphasize continuous improvement through lessons learned meetings.

3. **Key Concepts & Definitions:**
   - **Botnet:** Network of compromised computers used for attacks.
   - **DDoS:** Distributed Denial of Service.
   - **Exfiltration:** Unauthorized data transfer.
   - **Security Baseline:** A known good configuration for a system or network.
   - **File Hash Values:** Digital fingerprints for verifying file integrity.
   - **Sandbox:** Isolated environment for safe malware analysis.
   - **IDS/IPS:** Intrusion Detection/Prevention System.
   - **Host-based Monitor:** Software that monitors a single host for changes or suspicious activity.
   - **Precursor vs. Indicator:** Understand the difference in threat detection.

4. **Proactive vs. Reactive:**
   Incident response is heavily weighted towards proactive preparation and continuous learning (preparation, post-incident). Reactive measures (detection, containment, recovery) are critical but rely on good preparation.

5. **Training Is Essential:**
   Training must occur before an incident to ensure a well-coordinated and efficient response. It's an investment that pays off.

6. **"Answer the Tough Questions" as a Framework:**
   Use this as a mental checklist for evaluating any incident:
     - What happened?
     - How did we perform?
     - What can we improve?
     - What should we watch for next time? This demonstrates critical thinking beyond just listing steps.
