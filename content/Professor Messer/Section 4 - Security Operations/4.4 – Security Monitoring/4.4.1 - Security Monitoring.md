# Security Monitoring

## Introduction to Security Monitoring

- **Continuous Threat**: Attackers are always active, 24/7. Continuous monitoring of systems and services is necessary.
- **Monitor All Entry Points**: Keep an eye on logins, public services, data storage locations, and remote access points.
- **React to Security Events**: Monitor for account access, firewall rule changes, and initiate additional scans when needed.

### Status Dashboards

- Use dashboards to consolidate monitoring information for a quick overview of security posture.

---

## Monitoring Computing Resources

### Systems

- **Authentication**: Monitor logins from unusual or unexpected locations. This can indicate unauthorized access attempts.
- **Server Monitoring**:
  - Track service activity and ensure proper backup status.
  - Check software versions to identify outdated applications that need patching.

### Applications

- **Availability**: Ensure applications are up and responsive by monitoring uptime and response times.
- **Data Transfers**: Monitor data transfer rates for unusual spikes, which could indicate exfiltration attempts.
- **Security Notifications**: Maintain open communication with developers and manufacturers to stay updated on security patches and alerts.

### Infrastructure

- **Remote Access Systems**: Monitor VPN connections and other remote access points. Identify who is connecting from where.
- **Firewall and IPS Reports**: Analyze reports for changes in attack volume or types, providing early warnings of targeted attacks.

---

## Log Aggregation

### SIEM/SEM (Security Information and Event Manager)

- **Purpose**: Consolidate logs from various systems into a central database for easier analysis.
- **Sources**: Servers, firewalls, VPN concentrators, SANs, cloud services, switches, routers, etc.
- **Benefits**:
  - **Centralized Reporting**: All information in one place for easy reporting.
  - **Correlation of Data**: Comparison and correlation of disparate data.

---

## Scanning

### A Constantly Changing Threat Landscape

- New vulnerabilities are discovered daily. Organizations use many applications and services, making it hard to track all vulnerabilities.
- **Active Checks**: Scan systems and devices for operating system types and versions, device driver versions, installed applications, and potential anomalies.
- **Gather Raw Details**: Scanning creates a detailed database useful for comprehensive reports.

---

## Reporting

### Analyze Collected Data

- **Actionable Reports**: Generate insights that guide decision-making and next steps.
- **Status Information**: Report on devices that are up-to-date and in compliance with patches. Identify older, unsupported operating systems.
- **Determine Next Steps**: Quickly generate reports for new vulnerabilities to identify affected systems.

### Ad Hoc Information Summaries

- Perform "what-if" analyses, such as how many systems will be vulnerable when a specific OS reaches end-of-life in 6 months.

---

## Archiving

### Identify and Contain Breaches

- **IBM Security Report (2022)**: It takes an average of 9 months to identify and contain breaches. Attackers can move freely during this time.
- **Historical Data**: Archive security data over extended periods for forensic analysis after a breach is discovered.
- **Mandates**: Some state or federal laws, and organizational requirements, may mandate data archiving.

---

## Alerting

### Real-time Notification of Security Events

- Set up immediate alerts for unusual or suspicious activity, such as sudden increases in authentication errors or large file transfers.
- **Actionable Data**: Alerts should provide enough information for quick action. Use SMS/text messages, email, and security consoles/SOC dashboards.

---

## Alert Response and Remediation

### Quarantine

- Isolate compromised or suspicious systems to prevent the spread of potential threats like malware or attacker lateral movement.

### Alert Tuning

- Balance alert sensitivity to minimize false positives (legitimate activity mistakenly flagged) and false negatives (actual security events missed).
- This is an ongoing process that improves accuracy over time.

---

## Takeaways for an Exam

1. **Why Security Monitoring is Crucial**: Constant vigilance is necessary due to the 24/7 threat landscape. Monitor all entry points and critical resources.
2. **Key Areas for Monitoring**:
   - **Systems**: Authentication (especially unusual logins), server activity, backups, software versions.
   - **Applications**: Availability, data transfers, security notifications from vendors.
   - **Infrastructure**: Remote access, firewall/IPS reports.
3. **Role of SIEM/SEM (Log Aggregation)**: Understand its function in centralizing logs for unified analysis. Key benefits include centralized reporting and correlating events across different systems.
4. **Importance of Scanning**: Recognize the dynamic threat landscape and actively check systems for vulnerabilities.
5. **Actionable Reporting**: Reports should provide clear insights for decision-making, focusing on status (compliance, outdated systems) and "what-if" scenarios.
6. **Archiving for Forensics and Compliance**: Long-term data retention is crucial for post-incident investigation and meeting regulatory mandates.
7. **Alerting for Real-time Response**: Set up immediate alerts for security events to enable quick response and keep relevant personnel informed.
8. **Alert Tuning (False Positives vs. False Negatives)**: This involves balancing alert sensitivity to minimize false positives and negatives, an ongoing process that improves accuracy over time.
