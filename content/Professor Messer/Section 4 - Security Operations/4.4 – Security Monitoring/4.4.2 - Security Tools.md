# Security Tools Overview

## 1. Security Content Automation Protocol (SCAP)

### Problem
- **Inconsistent Reporting:** Many security tools on the market, such as NGFWs and vulnerability scanners, have their own unique ways of evaluating threats, logging information, and describing vulnerabilities. This leads to inconsistent reports.
- **Difficulty in Correlation:** Finding it challenging to correlate findings across different tools.
- **Increased Manual Effort:** Security teams spend more time manually handling these issues.

### Solution: SCAP (Security Content Automation Protocol)
- **Purpose:** Provides a standardized language for security tools, enabling them to identify and act on the same criteria. This ensures that all diverse security tools can use a common language to consolidate vulnerabilities.
- **Managed by:** National Institute of Standards and Technology (NIST) - [http://scap.nist.gov](http://scap.nist.gov)
- **Benefits:**
  - **Standardization:** All security tools identify the exact same vulnerability using a common language.
  - **Automation:** Tools can work together to automate validation, patch confirmation, scanning for breaches, and removal of vulnerabilities.

### Use Cases
- Configuration compliance
- Detecting applications with known vulnerabilities
- Especially useful in large environments with many operating systems and applications

## 2. Benchmarks

### Definition
A set of security best practices applied to various systems and environments. These represent the bare minimum for secure settings.

### Purpose
- Provides a baseline for secure configuration.
- Ensures that systems are "secure out of the box."

### Popular Benchmarks: Center for Internet Security (CIS)
[https://www.cisecurity.org/cis-benchmarks/](https://www.cisecurity.org/cis-benchmarks/)

### Example (Mobile Device Benchmark)
- Disable screenshots
- Disable screen recordings
- Prevent voice calls when locked
- Force encryption backups
- Disable additional VPN profiles
- Configure a "lost phone" message

## 3. Agents vs. Agentless

### Purpose: Methods to Check Compliance with Security Policies or Benchmarks

#### Agents
- **Mechanism:** A software agent is installed directly onto the device.
- **Advantages:**
  - Provides detailed information about the device's state.
  - Always monitoring for real-time notifications of changes or issues.
- **Disadvantages:**
  - Requires initial installation and setup.
  - Must be continually maintained and updated (agent code, data).

#### Agentless
- **Mechanism:** On-demand operation with low overhead.
- **Advantages:**
  - Not continuously monitoring, reducing load.
  - Lower maintenance requirements.

### Example Comparisons
- **Agents:** Detailed real-time information but require more maintenance.
- **Agentless:** Low overhead and on-demand operation but not continuous monitoring.

## 4. Security Information and Event Management (SIEM)

### Purpose: Centralized Logging and Analysis

#### Functionality
- Super-powered log aggregator that provides:
  - Real-time alerts
  - Long-term storage
  - Correlation capabilities
  - Forensic analysis

## 5. Anti-Virus/Anti-Malware

### Purpose: Identifying Potential Weaknesses in Systems and Applications

#### Nature: Minimally Invasive
- Detects vulnerabilities but does not attempt to exploit them.

#### Key Functions
- **Port Scan:** "Pokes around" devices to discover open ports and running services.
- **System Identification:** Identifies active systems within a specified IP range.
- **Vulnerability Detection:** Scans for known vulnerabilities, misconfigurations, and outdated software versions.

#### Testing Perspective
- **Outside:** Scans from an external perspective.
- **Inside:** Scans from the network to identify insider threats and internal misconfigurations.

### Example: Nessus Scan Results
- **Severity Categorization:** Critical, High, Medium, Low, Info.
- **Name:** Description of the vulnerability.
- **Family:** Type of issue (e.g., General, DNS, Web Servers).
- **Count:** Number of occurrences.
- **Scan Details:** Policy used, status, scanner, start/end times.

### Action: Regular Vulnerability Scans
- Identifies and remediates critical vulnerabilities before they can be exploited.

## 6. Data Loss Prevention (DLP)

### Purpose: Preventing Sensitive Data Leakage

#### Goal
- Identify and block sensitive data from leaving the network or being stored improperly.
- Often requires multiple solutions across endpoints and cloud services.

## 7. Simple Network Management Protocol (SNMP)

### Purpose: Network Monitoring

#### Key Components
- **MIB (Management Information Base):** A database of collected device data.
- **OIDs (Object Identifiers):** Numerical identifiers for specific metrics or data points within the MIB.

#### Polling (Default Operation)
- **Mechanism:** A network management station (NMS) periodically sends requests to devices over `udp/161`.
- **Function:** Requests statistics from various network devices.
- **Benefit:** Allows creation of historical performance graphs by collecting data at fixed intervals.

#### Drawback
- Requires constant polling; no data if the NMS doesn't poll.

### Solution: SNMP Traps

#### Mechanism
- Proactive alerts sent by monitored devices when a specified event or threshold occurs.
- Configured on the monitored device (SNMP agent).

#### Port: `udp/162`

#### Function
- Device sends a "trap" alert to the NMS when a condition is met.

### Benefit
- Allows immediate reaction to critical events, such as sending notifications or triggering automated remediation.

## 8. NetFlow

### Purpose: Gathering Traffic Statistics

#### Standard and Functions
- A standard collection method with many products available.
- **Probe:** Watches network communication (built into devices or external).
- **Collector:** Receives summary records from probes.
- **Reporting Application:** Used to create dashboards and reports.

#### Information Provided
- Top conversations, endpoints, traffic sources, application usage (HTTP, SQL, DNS), detailed traffic analysis events.

### Benefit
- Allows network administrators to analyze traffic flows for granular insights into application usage, bandwidth consumption, and potential security anomalies.

## Takeaways for Exam

1. **SCAP is about Standardization:** Remember NIST and its role in creating a common language for security tools.
2. **Benchmarks are Baselines:** CIS provides these critical benchmarks.
3. **Agents vs. Agentless:**
   - **Agents:** Detailed, real-time monitoring but require maintenance.
   - **Agentless:** On-demand operation with low overhead.
4. **SIEM is for Centralized Logging and Analysis:** Think of it as a super-powered log aggregator providing real-time alerts, long-term storage, correlation, and forensic capabilities.
5. **Anti-Virus/Anti-Malware are Merged:** Modern solutions offer comprehensive protection against a broad range of malicious software.
6. **DLP Prevents Data Leakage:** Identifies and blocks sensitive data from leaving the network or being stored improperly.
7. **SNMP for Network Monitoring:**
   - **MIBs (Management Information Bases)** store device data.
   - **OIDs (Object Identifiers)** are numerical IDs for specific metrics.
   - **Polling (UDP/161):** NMS requests data periodically.
   - **Traps (UDP/162):** Devices send alerts when thresholds are met.
8. **NetFlow for Traffic Statistics:** Gathers detailed information about all network traffic flows, useful for understanding application usage and bandwidth.
9. **Vulnerability Scanners are Minimally Invasive:** Identify weaknesses but do not exploit them. Results categorized by severity (Critical, High, Medium, Low, Info).
10. **Understand the "Why" for Each Tool:** What problem does it solve? What benefit does it provide to a security team?
11. **Key Organizations/Protocols:**
   - NIST (SCAP)
   - CIS (Benchmarks)
   - UDP/161 & UDP/162 (SNMP)
