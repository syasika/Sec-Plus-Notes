# Web Filtering - Professor Messer Notes

## Content Filtering

**Definition:** Controls traffic based on the data within the content rather than just where it’s going (ports/IPs). This goes beyond basic firewall rules, which often filter by port/application.

- **Examples:**
  - URL filtering
  - Website category filtering

**Purposes:**

1. **Corporate Control:** Manages outbound and inbound data flow.
   - **Preventing Exfiltration of Sensitive Materials**: Ensures sensitive information isn’t accidentally or maliciously shared.

2. **Inappropriate Content Control:** Restricts access to certain types of content.
   - **NSFW (Not Safe for Work) Content in Corporate Environments**
   - **Parental Controls** in Home Networks

3. **Protection Against Malicious Sites:** Blocks known malicious sites.
   - **Anti-Virus, Anti-Malware Protection**

## URL Scanning

**Mechanism:** Determines whether to allow or restrict access based on the Uniform Resource Locator (URL) or Uniform Resource Identifier (URI).

- **Management:**
  - Uses Allow Lists (whitelists) for permitted URLs and Block Lists (blacklists) for forbidden ones.
  - Can manage this by adding individual Fully Qualified Domain Names (FQDNs), but this is difficult to scale. Instead, categories are often used:
    - Auction
    - Hacking
    - Malware
    - Travel
    - Recreation
    - Adult
    - Educational
    - Gambling
    - Government
    - Home and Garden
    - Legal
    - News

**Limitations:**
- Primarily controls information seen inside a browser window.
- Does not inherently control other methods of accessing data on the internet (e.g., direct application connections).

**Integration:**
- Historically, standalone URL filters existed but are now commonly integrated into Next-Generation Firewalls (NGFWs).
- NGFWs provide a single device to manage:
  - Firewall rules
  - Intrusion Prevention Systems (IPS)
  - URL filtering

## Agent-Based Filtering

**Mechanism:** Uses client software ("agents") installed directly on user devices (desktop, laptop, mobile).

**Management:**
- Usually managed centrally from a console.
- Benefits:
  - **Location Independent**: Users can be located anywhere (e.g., working from home, traveling).
  - **Local Decision Making**: The local agent makes filtering decisions, ensuring "always-on, always filtering" protection regardless of network connection.

**Challenges:**
- **Updates**: Filters (lists of URLs/categories) must be constantly updated and distributed to all agents.
- Often uses cloud-based updates for efficiency.
- Update status is typically shown at the central console.

## Proxies

**Definition:** A device that sits between users and the external network, acting as an intermediary.

**How It Works:**
1. Receives user requests.
2. Sends the request on behalf of the proxy (acting as an intermediary).
3. Receives the response from the external server.
4. Makes a decision based on the response (filter, cache) before forwarding it to the user.

**Usefulness:**
- **Caching Information**: Stores frequently accessed web pages to speed up subsequent requests and reduce external bandwidth.
- **Access Control**: Limits which devices or users can communicate with the internet (e.g., based on username/password or IP address).
- **URL Filtering**: Intercepts and filters URLs.
- **Content Scanning**: Examines actual content for malicious code or inappropriate material.

**Types of Proxies:**

1. **Explicit Proxy**
   - Applications must be explicitly configured to use the proxy server.
   - The user or administrator is aware of the proxy's presence and has to set it up.

2. **Transparent Proxy**
   - Does not require special configuration on the client.
   - The user is often unaware that a proxy is being used.
   - Traffic is automatically redirected through the proxy by network devices.

### Forward Proxy

- **Definition:** A centralized "internal proxy" designed to protect and control user access to the internet (outbound traffic).
- **Location:** Both the user and the proxy are within the internal network of the organization.
- **Control:** The organization has control over the proxy's configuration.
- **Process:**
  1. User sends request to the internal proxy.
  2. Proxy makes its own request to the website on the internet.
  3. Website responds to the proxy.
  4. Proxy performs security checks (URL filtering, malware, etc.).
  5. Proxy sends the safe response back to the user.

## Block Rules & Dispositions

- **Based on Specific URL:**
  - Allows or blocks specific URLs based on their reputation.
  
- **Based on Categories:**
  - More commonly used for broader content control.
  - Examples include:
    - Trustworthy
    - Low risk
    - Medium risk
    - Suspicious
    - High risk

**Dispositions:**
- **Allow**: Site is considered safe and can be accessed.
- **Block**: Site is considered unsafe and cannot be accessed.
- **Allow and Alert**: Site can be accessed, but an alert is generated.

## Reputation-Based Filtering

**Mechanism:** Filters URLs based on the perceived risk associated with the website. A good reputation allows access; a bad reputation blocks it.

**Risk Categories:**
- Trustworthy
- Low risk
- Medium risk
- Suspicious
- High risk

**Reputation Assignment:**
- **Automated Reputation**: Sites are automatically scanned and assigned a reputation by security vendors or services.
- **Manual Reputation**: Administrators can override automated assessments if they disagree with the assessment.

## DNS Filtering

**Mechanism:** Provides content filtering by manipulating Domain Name System (DNS) lookups.

**How It Works:**
1. Before connecting to a website, the user's device performs a DNS lookup to get the corresponding IP address.
2. The DNS server used for filtering is constantly updated with real-time threat intelligence.
3. If a harmful domain is requested, the DNS server will not resolve it (i.e., it won't provide a valid IP address).

**Outcome:**
- No IP address returned.
- No connection can be made to the harmful site.
- The user might receive a "page not found" error or be redirected to a safe page.

## Takeaways for Exam Preparation

1. **Core Definition of Content Filtering**: Controls traffic based on what’s inside the data, not just where it goes (ports/IPs). Understand its three main purposes: corporate control, inappropriate content control, and protection against threats.
2. **URL Scanning vs. DNS Filtering**:
   - **URL Scanning**: Operates at the application layer (HTTP/HTTPS), typically within a browser or proxy. Filters based on full URLs or categories.
   - **DNS Filtering**: Operates at the network layer (DNS). Blocks access before a connection is even attempted by preventing the resolution of malicious domain names to IP addresses.

3. **Methods of Web Filtering Implementation**:
   - **URL Filtering (integrated into NGFW)**: Centralized, manages various security functions.
   - **Agent-Based**: Distributed, client-side software. Essential for mobile/remote users. Requires robust update mechanisms.
   - **Proxies**: Intermediary servers. Understand their role in caching, access control, and content inspection. Differentiate between explicit (client configured) and transparent proxies. Know that a forward proxy is an internal proxy for outbound user internet access.

4. **DNS Filtering**:
   - Blocks at the domain resolution level.
   - Highly effective against C2 traffic and general undesirable content.

5. **How Block Rules Are Applied**:
   - Can be based on specific URLs or categories.
   - Be familiar with dispositions (allow, block, allow and alert) and how they can be applied to different categories.

6. **Reputation-Based Filtering**:
   - Understand that sites are assigned a risk level (Trustworthy, Low, Medium, Suspicious, High).
   - Know that reputation can be automated or manual.
   - This is a dynamic way to filter based on current threat intelligence.

7. **Key Terms & Acronyms**:
   - URL: Uniform Resource Locator
   - URI: Uniform Resource Identifier
   - FQDN: Fully Qualified Domain Name
   - NGFW: Next-Generation Firewall
   - DNS: Domain Name System
   - C2: Command and Control (server)
   - Allow List / Block List
   - Explicit / Transparent Proxy
   - Forward Proxy

8. **Benefits and Drawbacks**: Consider the pros and cons of each filtering method, especially in different organizational contexts.
