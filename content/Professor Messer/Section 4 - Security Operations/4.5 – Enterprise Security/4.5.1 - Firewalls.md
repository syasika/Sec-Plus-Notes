# Firewalls & IPS Rules

## Overview

### Definition
- **Definition**: An appliance that sits inline in your network, making decisions about allowing or disallowing traffic.

### Traffic Filtering
- **Traditional Firewalls**: Filter primarily by port number (associated with OSI Layer 4 - Transport).
- **Next-Generation Firewalls (NGFW)**: Filter by application (associated with OSI Layer 7 - Application).

### Additional Services
- **Encrypt Traffic**: Can function as **VPN endpoints** or **VPN concentrators**.
    - Used for site-to-site VPNs.
    - Used for remote access VPNs.
- **Layer 3 Devices (Routers)**: Most firewalls can also act as routers.
    - Often placed at the ingress/egress points of the network (where external meets internal).
    - Perform **Network Address Translation (NAT)**.
    - Perform **Dynamic Routing** and other routing functions.

## Next-Generation Firewalls (NGFW)

### Core Functionality
- Operates at the OSI Application Layer (Layer 7 firewall).

### Advanced Analysis
- Able to analyze traffic flowing through and recognize specific applications being used.
    - Allows decisions based on *what* application is being used, not just *what port* it's using.

### Other Names
- **Application layer gateway**
- **Stateful multilayer inspection**
- **Deep packet inspection (DPI)**

### Processing Requirements
- Requires advanced decodes.
- Every packet must be analyzed, categorized, and a security decision determined.
    - This is more resource-intensive than traditional firewalls.

## Ports and Protocols

- Firewalls make forwarding decisions based on protocol (TCP or UDP) and port number.
- Traditional firewalls rely solely on this.
- NGFWs can add port numbers to their application-based policies for additional granularity.

### Common Protocols & Ports
- **Web server**: `tcp/80` (HTTP), `tcp/443` (HTTPS)
- **SSH server**: `tcp/22`
- **Microsoft RDP**: `tcp/3389`
- **DNS query**: `udp/53`
- **NTP**: `udp/123`

## Firewall Security Policies

- Firewall policies are a set of rules that dictate how traffic is handled.
- NGFW policies offer extensive parameters for decision-making beyond just source/destination IP and port. These include:
    - Zone (source/destination network segment)
    - Source/Destination IP Address
    - Service (port number)
    - User (authenticated user identity)
    - Application
    - Web Category
    - URL List
    - Custom Match criteria
    - Country (geographical location)
    - Schedule (time of day/week)
    - Security Profiles (e.g., antivirus, IPS)

## Firewall Rules

### Logical Path
- Firewall rules are evaluated in a logical path, typically top-to-bottom.
    - The first rule that a traffic flow matches will be applied, and no further rules are checked.

### Rule Specificity
- **Specific rules** are usually placed at the top of the rule list to be matched quickly.
- **General or broad rules** are placed lower down.

### Implicit Deny
- Most firewalls include an implicit deny at the very bottom of their rule base.
    - This means if traffic does not explicitly match any `allow` rule above it, it is automatically denied/dropped.
    - This is a fundamental security principle: "If it's not expressly permitted, it's forbidden."

### Access Control Lists (ACLs)
- Firewall rules are often referred to as Access Control Lists (ACLs).
- ACLs are groupings of categories (e.g., Source IP, Destination IP, port number, time of day, application) to allow or disallow traffic.

### Example: Web Server Firewall Ruleset

| Rule Number | Remote IP     | Remote Port | Local Port | Protocol | Action  |
|-------------|---------------|-------------|------------|----------|---------|
| 1           | All           | Any         | 22         | TCP      | Allow   | (SSH)   |
| 2           | All           | Any         | 80         | TCP      | Allow   | (HTTP)  |
| 3           | All           | Any         | 443        | TCP      | Allow   | (HTTPS) |
| 4           | All           | Any         | 3389       | TCP      | Allow   | (RDP)   |
| 5           | All           | 53          | Any        | UDP      | Allow   | (DNS Query) |
| 6           | All           | 123         | Any        | UDP      | Allow   | (NTP)   |
| 7           | All           | Any         | Any        | ICMP     | Deny    | (Ping)  |
| (Implicit)  | Any           | Any         | Any        | Any      | Deny    | (Default)|

## Screened Subnet (DMZ)

### Definition
- An additional layer of security between your internal network and the Internet.

### Purpose
- Used for public-facing services to isolate them from the internal network.
- Prevents direct access to internal systems from the Internet or DMZ without explicit allow rules.

### Typical Placement
- Located between external and internal networks in a network architecture.

## IPS Rules

### Intrusion Prevention System (IPS)
- A security device that monitors network traffic for malicious activity and takes action to prevent threats.
- Usually integrated into an NGFW today.

### How IPS Finds Malicious Traffic
- **Signature-based**: Looks for a perfect match to known attack patterns (signatures).
    - Example: A specific sequence of bytes in a packet known to be from a Conficker worm shellcode.
    - Effective against known threats.
- **Anomaly-based**: Builds a baseline of what "normal" traffic looks like and flags unusual traffic patterns as potential intrusions.
    - Example: A sudden spike in traffic, or traffic to an unusual port.
    - Effective against unknown/zero-day threats but can have higher false positives.

### Actions When Unwanted Traffic Appears
- **Block** the traffic.
- **Allow** the traffic (if deemed safe after inspection, or for specific exceptions).
- **Send an alert** to administrators.
- **Drop** the connection.
- **Reset** the connection.

### Rule Management
- IPS systems often contain thousands of rules.
    - Rules can be customized by group (e.g., block all known database injection attempts) or as individual rules.
    - Challenge: Finding the right balance between security, alert "noise," and false positives. This requires careful tuning.

# Exam Takeaways

1. **Distinguish Traditional vs. NGFW**
    - **Traditional**: OSI Layer 4 (Transport), filters by port number and protocol.
    - **NGFW**: OSI Layer 7 (Application), filters by application in addition to ports/protocols. Understands HTTP, SSH, RDP, etc., as applications.
    - NGFWs perform "Deep Packet Inspection" (DPI) and are more resource-intensive due to this deeper analysis.

2. **Firewall Capabilities Beyond Filtering**
    - Firewalls are often Layer 3 devices (routers).
    - They perform NAT and dynamic routing.
    - They can act as VPN endpoints/concentrators for encrypted traffic.

3. **Firewall Rule Logic is Critical**
    - Rules are processed top-to-bottom. Order matters! Place specific `ALLOW` rules at the top, followed by more general `ALLOW` rules.
    - The implicit deny rule at the bottom is crucial: if traffic doesn't match an explicit `ALLOW` rule, it's automatically denied.
    - Be able to interpret a simple firewall ruleset (like the example provided).

4. **Key Terms & Synonyms**
    - **ACLs** = Firewall rules/policy lists.
    - **Screened Subnet** = **DMZ (Demilitarized Zone)**. Understand its purpose and typical placement in a network architecture (between external and internal networks for public-facing services).
    - NGFW synonyms: Application layer gateway, Stateful multilayer inspection, Deep packet inspection.

5. **Common Ports & Protocols**
    - Memorize the common ports and their associated protocols (TCP/UDP) as given in study materials.
        - HTTP (80/TCP), HTTPS (443/TCP), SSH (22/TCP), RDP (3389/TCP), DNS (53/UDP), NTP (123/UDP), ICMP (no port, but often denied).

6. **Intrusion Prevention Systems (IPS)**
    - Understand its role as a proactive security measure, often integrated into NGFWs.
    - Differentiate between signature-based and anomaly-based detection methods.
    - Know the possible actions an IPS can take (block, alert, drop, reset).
    - Be aware of the operational challenge of false positives and the need to tune IPS rules.
