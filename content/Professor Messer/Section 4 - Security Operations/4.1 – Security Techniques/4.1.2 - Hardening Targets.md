# Hardening Targets

## Introduction to Hardening
- **Core Principle:** No system is secure with default configurations. Security posture can be significantly improved by following specific guidelines.
- **Necessity:** It's essential to have detailed security recommendations to protect systems effectively.
- **Hardening Guides:**
  - These are often specific to software or platforms like operating systems and applications.
  - Best practices come from the manufacturer or relevant internet interest groups, with third-party guides also available.

## Mobile Devices
- **Characteristics:** Always-connected technologies such as phones and tablets.
- **Hardening Checklist/Suggestions from Manufacturers:**
  - Always refer to manufacturer guidelines for specific hardening steps.
- **Updates are Critical:**
  - Regular updates include bug fixes and security patches, preventing known vulnerabilities.
- **Segmentation Protects Data:**
  - Separate company data from user/personal data (logical separation) using different network segments.
  - This limits attacker access if one segment is compromised.
- **Control with an MDM (Mobile Device Manager):**
  - An MDM can manage and push security updates/configurations to large groups of devices, ensuring consistent security policies.

## Workstations
- **Targets:** User desktops and laptops running various operating systems like Windows, macOS, or Linux.
- **Constant Monitoring and Updates:**
  - Regularly update the operating system, applications, and firmware to address bugs and security vulnerabilities.
- **Automate Monthly Patches:**
  - Many companies release patches on a schedule (e.g., Patch Tuesday).
  - This allows testing all patches before deployment.
- **Connect to a Policy Management System:**
  - Examples include Active Directory Group Policy.
  - These systems enforce consistent security settings across multiple workstations.
- **Remove Unnecessary Software:**
  - Every piece of software increases the attack surface, so uninstall unneeded applications.

## Network Infrastructure Devices
- **Targets:** Switches, routers, and firewalls (often unseen but always present).
- **Characteristics:**
  - These are purpose-built devices often running embedded operating systems with limited access.
- **Configure Authentication:**
  - Change default credentials immediately.
  - Use strong, unique passwords or central authentication mechanisms like RADIUS or TACACS+.
- **Check for Security Updates:**
  - Although updates aren't frequent, they are critical when available.
  - Apply patches to address vulnerabilities in the embedded firmware/OS.

## Cloud Infrastructure
- **Target:** The cloud management workstation (often referred to as the "keys to the kingdom").
- **Secure the Cloud Management Workstation:**
  - Ensure this device is highly secure due to its access to all cloud-based systems.
- **Least Privilege:**
  - Configure services, network settings, application rights, and permissions to the minimum required for their function.
- **Configure EDR (Endpoint Detection and Response):**
  - Monitor potential attacks and ensure devices are up-to-date with anti-malware technologies.
- **Always Have Backups:**
  - Cloud-based devices can be prone to outages.
  - Implement cloud-to-cloud (C2C) backups to a separate provider as best practice.

## Servers
- **Targets:** Windows, Linux servers, and other server environments.
- **Updates:**
  - Promptly apply operating system updates/service packs and security patches.
  - Keep the OS secure by installing necessary patches promptly.
- **User Accounts:**
  - Implement strong password policies (minimum lengths and complexity).
  - Limit account usage (disable unused accounts, enforce least privilege).
- **Network Access and Security:**
  - Restrict network access via server-side policies or firewalls.
  - Limit communication to a set number of devices/services.
- **Monitor and Secure:**
  - Deploy anti-virus, anti-malware, EDR, or other client-based security technologies.

## SCADA / ICS (Supervisory Control and Data Acquisition System / Industrial Control Systems)
- **Characteristics:**
  - Large-scale industrial control systems managing critical equipment like power generation, refining, manufacturing, facilities, energy, logistics.
  - Often use distributed control systems for real-time information and system control.
- **Requires Extensive Segmentation:**
  - Typically well-secured with their own isolated network (air gap) to limit access from the outside or internet.

## Embedded Systems
- **Characteristics:**
  - Hardware and software designed for specific functions like smartwatches, televisions, or purpose-built appliances.
  - Limited OS access makes upgrading difficult, and security patches may be rare.
- **Correct Vulnerabilities:**
  - Install security patches as soon as available if possible.
- **Segmentation and Firewall:**
  - Place embedded devices on their own segmented network (e.g., VLAN).
  - Use a firewall to prevent unauthorized access.

## RTOS (Real-Time Operating System)
- **Characteristics:**
  - An operating system with deterministic processing, critical for precise timing in industrial equipment, automobiles, military environments.
- **Isolate the System:**
  - Prevent other network areas from accessing it.
  - Ensure no device can affect its running state.
- **Run with Minimum Services:**
  - Enable only necessary services to prevent potential exploits.
- **Use Secure Communication:**
  - Protect communication using host-based or network firewalls if external access is required.

## IoT Devices
- **Targets:** Home automation, heating and cooling systems, wearable technology.
- **Weak Defaults:**
  - IoT manufacturers often lack security expertise, leading to weak default passwords.
- **Change Default Passwords:**
  - Changing the default password is crucial.
- **Deploy Updates Quickly:**
  - Prioritize patching immediately due to vulnerabilities in IoT devices.
- **Segmentation:**
  - Place IoT devices on their own VLAN to limit potential exploit scope.

# Exam Takeaways

## Core Principles of Hardening
1. **Default Configurations are Insecure:** Always assume factory settings pose a security risk and change them.
2. **Specific Guidance is Key:** Hardening isn't one-size-fits-all; always look for manufacturer-specific guides or trusted community resources.
3. **Patch Management is Paramount:** Regularly applying bug fixes and security patches prevents known vulnerabilities from being exploited.
4. **Least Privilege:** Granting only the minimum necessary rights reduces the impact of a compromise.
5. **Segmentation:** Isolating different systems or data limits attackers' ability to move laterally and contain breaches.
6. **Remove Unnecessary Components:** Eliminating unused software, services, or open ports reduces attack surfaces.
7. **Strong Authentication:** Implementing strong passwords, multi-factor authentication, and robust mechanisms is essential.

## Key Differences & Specific Considerations
- **Mobile Devices:** Focus on manufacturer checklists, MDM for enterprise management, critical updates, and data segmentation (company vs. personal).
- **Workstations:** Emphasize continuous monitoring, automated patching, policy management, and software removal.
- **Network Infrastructure Devices:** Recognize their embedded nature; changing default credentials and applying firmware updates is crucial.
- **Cloud Infrastructure:** Secure the cloud management workstation with least privilege, EDR, and C2C backups.
- **SCADA/ICS:** Use extensive segmentation to ensure air-gapped networks with no external access.
- **Embedded Systems:** Focus on patching if possible, and use segmentation as a compensatory control.
- **RTOS (Real-Time Operating Systems):** Ensure extreme isolation, run minimal services, and secure communication for uninterrupted operation.
- **IoT Devices:** Change default passwords first, then rapidly apply patches and segment them using VLANs.

## Exam Questions to Anticipate
1. **Scenario-Based:** Given a specific system (e.g., an IoT device, cloud server, SCADA system), list the top 3-5 hardening steps and explain why.
2. **Definition/Concept:** Explain "least privilege" or "segmentation" in the context of hardening.
3. **Comparison:** Compare hardening challenges and solutions for two different target types (e.g., mobile devices vs. network infrastructure).
4. **Best Practices:** List general best practices for hardening any system.
5. **Vulnerability Mapping:** Describe how a lack of hardening can lead to specific vulnerabilities (e.g., default passwords leading to unauthorized access).
6. **Tool/Technology:** Identify tools or technologies that aid in hardening (e.g., MDM, EDR, policy management systems).

By understanding these categories and specific hardening actions for each, you'll be well-prepared for an exam on "Hardening Targets."
