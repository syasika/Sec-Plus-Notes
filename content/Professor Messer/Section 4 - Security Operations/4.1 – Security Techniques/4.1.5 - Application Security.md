# Application Security

## Overview

- **Definition**: The practice of protecting applications from vulnerabilities that can lead to data breaches or other security issues.

---

## Secure Coding Concepts

### Challenge of Application Development

Creating applications requires significant complexity, often leading developers to prioritize speed over security. This can result in neglecting secure coding practices, making applications more vulnerable.

### Importance of Testing

- **Quality Assurance (QA)** is crucial for ensuring both functionality and security.
- Many common vulnerabilities, such as buffer overflows or SQL injection, are typically discovered during this process.
- Even with thorough QA testing, vulnerabilities will eventually be found by internal researchers or attackers. Attackers will then exploit these weaknesses.

---

## Input Validation

### Core Concept

Input validation ensures that data entered into an application is clean, correct, and safe to process. Developers must define expected input types for every field and validate actual inputs against those expectations.

### Documentation and Normalization

- **Documentation**: Document all input methods, including forms, fields, and data types.
- **Normalization**: Transform input into a standardized format. For example, a zip code should only contain numeric characters or alphanumeric values based on the country.
- **Correction**: Fix any improperly formatted data or prompt users for correction.

### Fuzzing

Fuzzing is an automated process of providing varied, unexpected, or malformed inputs to discover vulnerabilities or crashes. Proper input validation can prevent attackers from exploiting these weaknesses.

---

## Secure Cookies

### What are Cookies?

Cookies store small pieces of information on the user's computer via their browser. They are used for tracking activity, personalization, and session management.

### Security Implications

- **Not Executable**: While not malware, cookies can contain sensitive data that unauthorized access could exploit.
- **Secure Attribute**: Setting a "Secure" attribute ensures cookies are only sent over HTTPS, preventing eavesdropping.
- **Limited Security**: Cookies themselves do not provide strong security. Information stored in them is easily accessible via browser tools.

Sensitive information should never be saved in cookies due to their limited security features.

## Static Code Analyzers

### Static Application Security Testing (SAST)

- **Definition**: SAST analyzes application source code, bytecode, or binary code without executing the application.
- **Benefits**: Identifies common vulnerabilities like buffer overflows and SQL injections early in development.
- **Limitations**: Cannot detect all issues, such as authentication logic flaws or insecure cryptography implementation details.

### Verification

Developers must verify each finding from static analyzers to avoid false positives. These tools often recommend safer alternatives for risky functions.

---

## Code Signing

### Purpose

Code signing verifies the integrity and authenticity of application executables or scripts.

- **Integrity**: Ensures that applications have not been tampered with.
- **Authenticity**: Confirms the developer's identity through a trusted Certificate Authority (CA).

### Process

- **Digital Signature**: The code is signed using the developer’s private key after being certified by a CA.
- **Verification**: When installed, the operating system checks the signature to ensure the application has not been altered.

Internal applications can use an organization’s own CA for signing.

---

## Sandboxing

### Core Concept

Sandboxing isolates applications in an environment where they cannot access unrelated resources. This limits damage from malicious or exploited code.

### Use Cases

- **Development**: Provides a safe space to test and develop code without affecting production systems.
- **Production**: Run untrusted or potentially vulnerable applications securely.

### Implementations

- **Virtual Machines (VMs)**: Each VM operates independently, isolated from others.
- **Mobile Devices**: Apps run with limited permissions, such as a browser app not being able to access your camera roll without permission.
- **Browser Iframes**: Web content within an iframe is sandboxed, limiting its interaction with the parent page.
- **Windows User Account Control (UAC)**: Prompts users for elevated privileges when needed.

---

## Application Security Monitoring

### Purpose and Key Activities

- **Real-time Information**: Monitor application usage patterns and access demographics to detect unusual activity.
- **View Blocked Attacks**: Track attempts at SQL injection, Cross-Site Scripting (XSS), and other attacks that the application successfully blocks.
- **Audit Logs**: Analyze logs to identify hidden threats or ongoing attacks using anomaly detection.

### Anomaly Detection

Detect unusual activities such as unexpected file transfers or sudden spikes in client access from unfamiliar locations. This helps uncover unknown vulnerabilities or sustained attacks.

---

## Exam Takeaways

1. **Secure Coding is Foundational**: Secure coding practices must be integrated early and continuously throughout development.
2. **Input Validation is Paramount**: Validate all input against expected formats to prevent common attacks like SQL injection and buffer overflows.
3. **Cookies are Data, Not Code**: While not executable, cookies can contain sensitive information that should never be stored directly.
4. **SAST for Early Flaw Detection**: Use static code analysis tools to find vulnerabilities early in the development process.
5. **Code Signing for Trust and Integrity**: Ensure application integrity and authenticity through digital signatures.
6. **Sandboxing for Isolation**: Isolate applications to limit damage from malicious or exploited code.
7. **Monitoring is Continuous Vigilance**: Use monitoring tools to gain real-time insights into potential security threats and unusual activities.
