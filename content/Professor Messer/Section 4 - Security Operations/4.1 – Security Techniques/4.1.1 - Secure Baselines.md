# Secure Baselines

## Introduction to Secure Baselines

**Definition**: A well-defined set of security configurations and settings that an application environment must adhere to, including the application, operating system, and network devices.

**Purpose**: Ensures consistent security across all instances of an application.

**Components Included**:
- Firewall settings
- Patch levels (OS and applications)
- Operating system file versions
- Application-specific configuration settings

**Dynamic Nature**: Requires constant updates due to evolving threats and software changes.

## Integrity Measurements for Secure Baselines

**Continuous Monitoring**: Baselines must be frequently checked to ensure they remain effective.

**Process**:
1. Perform integrity checks.
2. Compare current configurations against the documented secure baselines.
3. **Correction**: Any deviations or failures necessitate immediate correction.

## Establishing Baselines

**Foundational Security Policies**: Start by creating a series of these policies.

**Leveraging Manufacturer Resources**:
- **Application Developer**: Provides baselines for specific applications (e.g., file permissions, internal config settings).
- **Operating System Manufacturer**: Offers security baselines for their OS (e.g., Microsoft provides extensive guidance and tools like the Security Compliance Toolkit for Windows 10, including over 3,000 Group Policy settings).
- **Appliance Manufacturer**: Provides baselines for hardware appliances.

## Deploying Baselines

**Putting Baselines into Action**: Once established, these detailed security baselines need to be deployed across all relevant components.

**Centralized Management**: Often managed through a centrally administered console (e.g., Microsoft Security Compliance Toolkit).

**Multiple Deployment Mechanisms**:
- **Active Directory Group Policy (GPO)**: For Windows domain-joined systems.
- **Mobile Device Management (MDM)**: For mobile devices.
- Other configuration management tools.

**Automation is Key**: Essential for large environments to ensure efficiency and consistency in deployment.

## Maintaining Baselines

**Best Practices vs. Ongoing Updates**:
- Many baseline settings are based on best practices and rarely change.
- Others require ongoing updates due to new vulnerabilities, application updates, or operating system installations/upgrade.

**Conflict Resolution**: Different manufacturers' baselines might contradict each other, requiring careful evaluation for the best fit.

**Testing and Measuring**:
- **Pre-deployment Testing**: Crucial to test baselines before full deployment.
- **Post-deployment Auditing**: Regularly audit deployed baselines to ensure they remain effective.

## Exam Takeaways

1. **Core Definition & Purpose**: A secure baseline is a defined, consistent set of security configurations for an application environment. Its primary purpose is to ensure a strong and consistent security posture across all instances.
2. **Key Components**: Secure baselines cover more than just the application itself; they include firewall settings, patch levels, OS file versions, and other underlying infrastructure components.
3. **Lifecycle**: Secure baselines follow a distinct lifecycle: Establishment -> Deployment -> Maintenance.
4. **Establishment Sources**:
    - Application developers
    - Operating system manufacturers (e.g., Microsoft provides extensive guidance)
    - Appliance manufacturers.
5. **Deployment Mechanisms**:
    - Centralized consoles
    - Active Directory Group Policy (GPO) for Windows domain-joined systems
    - Mobile Device Management (MDM) for mobile devices
    - Automation is critical for large-scale deployments.
6. **Maintenance Triggers**: Scenarios that necessitate updating baselines include new vulnerabilities, application updates, and OS installations or upgrades.
7. **Challenges in Maintenance**:
    - Conflicts between different vendor baselines require careful evaluation.
    - Enterprise environments are complex, making maintenance challenging.
8. **Verification**: Integrity measurements, frequent checks, and regular auditing ensure baselines remain effective and haven't drifted; immediate correction is required upon failure.
9. **Testing**: Testing baselines before deployment is crucial to prevent conflicts and ensure operational continuity.
