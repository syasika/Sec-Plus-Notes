# Application Attacks

## 1. Injection Attacks

### Definition
Injection attacks involve adding malicious information (often code) into a data stream that is then executed by the server or client device.

### Enabling Factor
These attacks occur due to poor programming practices where applications fail to properly handle or validate input and output.

### Injectable Data Types
Many types of data can be injected, including:
- **HTML**
- **SQL** (a common type)
- **XML**
- **LDAP**

### Analogy
Imagine using an air gun to inject something into a system; injection attacks use malicious code to "infect" the application.

## 2. Buffer Overflows

### Definition
A buffer overflow occurs when an application tries to write more data into a fixed-size memory buffer than it can hold, causing data to spill over into other adjacent memory areas.

### Enabling Factor
This happens because developers often lack bounds checking; they don't verify if the input data size exceeds the buffer's capacity.

### Impact
- **Crashes and Denial of Service:** The application may crash or become unresponsive.
- **Execution of Arbitrary Code:** Attackers can overwrite return addresses or other critical data in memory to execute their own code.

### Exploit Difficulty
Creating a successful exploit is not simple. It requires significant time and effort, often involving finding precise "openings" (vulnerable code paths).

### Useful Overflow
A truly useful buffer overflow is **repeatable**; it consistently compromises the system without crashing it.

### Analogy
Think of overfilling a birdbath—just like how water spills out into the surrounding area, data spills into other memory areas.

## 3. Replay Attack

### Definition
This attack involves capturing and replaying useful information (such as authentication credentials or session tokens) transmitted over a network to gain unauthorized access.

### Prerequisites
For this to work, attackers need access to raw network data, which can be achieved via:
- **Network tap**
- **ARP poisoning**
- **Malware on the victim's computer**

### Impact
The attacker can impersonate someone else and gain access to applications or systems. However, it is not an on-path attack itself; it relies on other attacks like Man-in-the-Middle (MitM) for initial data capture.

### Analogy
A "COPY" stamp works similarly to how a replay attack copies legitimate data and reuses it.

## 4. Privilege Escalation

### Definition
Privilege escalation is the process of gaining higher-level access than originally authorized, often by exploiting vulnerabilities in application code or system design flaws.

### Enabling Factor
Exploiting bugs or design flaws can lead to unauthorized access with greater privileges.

### Impact
This can result in significant security concerns, such as gaining System Administrator rights (highest-level access).

### Types of Privilege Escalation

- **Vertical Privilege Escalation:** Moving from a lower privilege level to a higher one.
- **Horizontal Privilege Escalation:** Moving between users at the same privilege level.

### Priority
These vulnerabilities need prompt attention as any user could potentially become an administrator.

### Analogy
Imagine an escalator going up—each step represents a mitigation technique to prevent reaching the top (highest privilege).

#### 4.1 Mitigating Privilege Escalation

- **Patch Quickly:** Fix vulnerabilities in operating systems and applications.
- **Update Anti-virus/Anti-malware Software:** Block known exploits targeting privilege escalation vulnerabilities.
- **Data Execution Prevention (DEP):** Marks memory areas as non-executable to block buffer overflow exploits.
- **Address Space Layout Randomization (ASLR):** Randomly arranges memory addresses, making it harder for attackers to predict locations.

### Example: Elevation of Privilege Vulnerability

- **CVE-2023-29336:** A Win32k Elevation of Privilege Vulnerability announced in May 2023.
- **Affected Systems:** Windows Server 2008, 2008 R2, 2012, 2012 R2, 2016, and Windows 10.
- **Impact:** An attacker exploiting this vulnerability gains SYSTEM privileges.

## 5. Cross-Site Request Forgery (CSRF / XSRF)

### Definition
CSRF is a "one-click attack" or "session riding," where an attacker takes advantage of the trust a web application has for a logged-in user's browser.

### Mechanism
The attacker crafts malicious requests hidden in links, images, or scripts and tricks the victim (who is already logged into a legitimate website) into unknowingly sending these requests to the trusted server.

### Impact
Trusted servers process the request as if it came from the legitimate user without their consent or knowledge. For example, an attacker might send you a malicious link that causes your browser to post a status update on your Facebook account without your awareness.

### Mitigation
Applications must implement anti-forgery techniques, such as including cryptographic tokens in every sensitive request and verifying these tokens on the server side.

### Analogy
A "FRAUD" stamp works by tricking a trusted entity (your browser/the website) into performing fraudulent actions.

## 6. Directory Traversal (Path Traversal)

### Definition
This attack allows an attacker to read or write files from a web server outside of its designated file directory, such as `wwwroot`.

### Impact
Attackers can access sensitive system files or write malicious files to critical locations on the server.

### Enabling Factors

- **Web Server Software Vulnerability:** The web server has a flaw that allows users to browse past its root directory.
- **Web Application Code Vulnerability:** Badly written code processes user input without proper validation, allowing directory traversal characters like `../`.

### Common Indicator
The use of `../` (dot-dot-slash) in URL parameters moves up one directory level. For example: `http://www.example.com/show.asp?view=../../Windows/system.ini` attempts to access the system file.

### Analogy
Navigating a file system, but being able to go outside the allowed boundaries.

# Exam Takeaways

1. **Know Your Definitions:** Be able to clearly define Injection, Buffer Overflow, Replay Attack, Privilege Escalation (vertical/horizontal), Cross-Site Request Forgery (CSRF/XSRF), and Directory Traversal.
2. **Understand Root Causes:** Identify the underlying vulnerability or programming flaw for each attack (e.g., improper input validation, lack of bounds checking).
3. **Identify Consequences:** Understand the impact of successful attacks, such as arbitrary code execution, data manipulation, unauthorized access, identity theft, and system control.
4. **Distinguish Similar Attacks:**
    - **Injection vs. Buffer Overflow:** Both involve sending too much or malicious data but differ in that injection interprets it as code (SQL, HTML), while buffer overflow overwrites memory locations.
    - **Replay Attack vs. CSRF:** Replay uses captured legitimate data to re-authenticate or re-execute actions, whereas CSRF leverages the browser's existing authentication and trust.

5. **Mitigation Strategies:**
    - **General:** Prompt patching, up-to-date anti-malware.
    - **Specific:**
        - **Injection:** Input validation, parameterized queries.
        - **Buffer Overflow:** Bounds checking, DEP, ASLR.
        - **Replay:** Nonces, timestamps, strong session management, encryption.
        - **Privilege Escalation:** Quick patching, DEP, ASLR, principle of least privilege.
        - **CSRF:** Anti-forgery tokens (cryptographic tokens in requests).
        - **Directory Traversal:** Input validation (sanitizing `../`), proper web server configuration.

6. **Recognize Indicators:** Spot common signs like `../` in URLs for directory traversal or special characters in input fields indicating SQL injection.
7. **Real-World Examples:** Remember CVE-2023-29336 as a high-impact example of privilege escalation.
8. **Client-Side vs. Server-Side:** Understand how different parts of web page code run and how this relates to attacks like CSRF, where the server trusts the browser's session.
