# DNS Attacks

## 1. DNS Poisoning

### Definition
DNS poisoning, also known as DNS spoofing, refers to an attack where an attacker modifies DNS resolution to redirect users to a malicious IP address instead of the legitimate one they intended to visit.

### Attack Vectors

#### Modifying the DNS Server
- **Description:** This involves gaining access to and modifying the actual DNS server.
- **Requirements:** High hacking skills and administrative credentials or vulnerabilities in the system.
- **Impact:** If successful, all users relying on that compromised DNS server would be redirected.
  
#### Modifying the Client Host File
- **Description:** The `hosts` file (local to a client machine) takes precedence over DNS queries.
- **Requirements:** Access and elevated rights on the client computer to modify this file.
- **Impact:** Only the compromised client machine is affected.

#### Sending a Fake Response to a Valid DNS Request
- **Description:** This requires the attacker to be "on-path" (e.g., Man-in-the-Middle attack).
- **Mechanism Example:**
  - **Normal Process:** User 1 queries DNS server for `professormesser.com`. The DNS server responds with `162.159.246.164`. User 1 caches this and connects.
  - **Poisoned Process:**
    1. Attacker gains control/access to the DNS server (e.g., through vulnerability or stolen credentials).
    2. The attacker modifies the DNS server's record for `professormesser.com` to point to their malicious IP (`100.100.100.100`).
    3. User 2 queries the DNS server for `professormesser.com`.
    4. The now-poisoned DNS server responds with `100.100.100.100` (the attacker's IP).
    5. User 2 caches this malicious IP and attempts to connect, but is redirected to the attacker’s server.
- **Impact:** All users querying the compromised DNS server will receive the malicious IP.

## 2. Domain Hijacking

### Definition
Domain hijacking involves gaining unauthorized control over a domain's registration with the domain registrar. This gives the attacker full control over where the domain's traffic flows, without needing to touch the actual DNS servers or client machines.

### Methods to Gain Access to the Domain Registration Account
- **Brute force attacks on the registrar account.**
- **Social engineering to trick the legitimate owner into revealing credentials.**
- **Accessing the email address that manages the domain account (e.g., through phishing or compromised email).**
- **Exploiting publicly released credentials or vulnerabilities in the registrar's system.**

### Real-world Example: Brazilian Bank Hack
- **Date:** Saturday, October 22, 2016, at 1 PM.
- **Scope:** Domain name registrations of 36 domains were changed.
- **Target:** A Brazilian bank, affecting desktop domains, mobile domains, and other associated devices.
- **Duration:** The domains were under hacker control for 6 hours.
- **Consequence:** The attackers effectively "became the bank," intercepting traffic, potentially collecting usernames, passwords, and other sensitive financial data.
- **Scale:** The bank had 5 million customers and $27 billion in assets.
- **Outcome:** Results of the hack were not publicly released, highlighting the severity and potential for significant damage.

## 3. URL Hijacking

### Definition
URL hijacking (also known as typosquatting or brandjacking) involves registering a domain name that is very similar to a legitimate one, often exploiting common typos or misspellings, to redirect users to a malicious or unwanted site.

### Motives/Tactics
- **Monetization through Advertising:** Redirecting users to sites filled with advertisements.
- **Selling Misspelled Domain:** Registering a typo-domain and then selling it to the actual owner for a profit (extortion).
- **Redirect to a Competitor:** Maliciously redirecting traffic from a legitimate site to a competitor's site (less common due to legal issues).
- **Phishing Site:** Directing users to a fake website that looks exactly like the real one to steal login credentials.
- **Infect with Drive-by Download:** Redirecting users to a site that automatically downloads malware (e.g., ransomware, botnet software) without user interaction.

### Types of Typosquatting/Brandjacking
- **Outright Misspelling:** `professormesser.com` vs. `professormessor.com`.
- **Typing Error:** `professormesser.com` vs. `professormeser.com`.
- **A Different Phrase:** `professormesser.com` vs. `professormessers.com`.
- **Different Top-Level Domain (TLD):** `professormesser.com` vs. `professormesser.org`.

### Prevention
Always be cautious of links in emails and carefully inspect the URL in your browser's address bar to ensure you are on the legitimate website.

## Takeaways for Exam

1. **Understand DNS’s Role:** DNS is fundamental for mapping human-readable domain names to machine-readable IP addresses. Its integrity is critical for secure internet navigation.
2. **Differentiate Between Types of Attacks:**
    - **DNS Poisoning:** Manipulating DNS records or caches (server-side) or client-side host files to redirect traffic.
        - *Server-side:* Requires admin access to the DNS server.
        - *Client-side:* Modifying the local `hosts` file (requires elevated client privileges).
        - *On-path:* Intercepting DNS queries and sending fake responses in real-time.
    - **Domain Hijacking:** Gaining control of a domain's registration at the registrar level, allowing full control over its DNS settings. This is a higher-level compromise than just poisoning a server's cache.
    - **URL Hijacking (Typosquatting/Brandjacking):** Registering new domain names that are intentionally similar to legitimate ones to trick users who make typing errors or don't scrutinize URLs closely.
3. **Identify Attack Motives:** Attackers use these methods for:
    - **Redirection:** Sending users to malicious sites.
    - **Credential Theft (Phishing):** Presenting fake login pages.
    - **Malware Distribution:** Initiating drive-by downloads (ransomware, botnets).
    - **Financial Gain:** Through advertising or selling hijacked domains back to owners.
    - **Reputation Damage:** Redirecting to competitor sites or inappropriate content.
4. **Recognize Common Typosquatting Techniques:**
    - Misspellings (e.g., `messor` instead of `messer`).
    - Typing errors (e.g., `meser` instead of `messer`).
    - Adding or removing letters/phrases (e.g., `messers`).
    - Using different Top-Level Domains (TLDs) (e.g., `.org` instead of `.com`).
5. **Understand Prevention Strategies:**
    - **For Organizations:** Secure DNS servers and registrars with strong authentication, multi-factor authentication (MFA), and regular security audits. Patch vulnerabilities promptly. Monitor DNS changes and registrations. Register common misspellings or related TLDs to prevent typosquatting.
    - **For Users:** Verify URLs carefully before clicking, especially in emails or unexpected messages. Manually type URLs for sensitive sites (like banking). Use reputable DNS resolvers (e.g., Google DNS, Cloudflare DNS). Keep operating systems and browsers updated. Use antivirus/anti-malware software. Be aware that `hosts` file modification requires elevated privileges, so good user account control helps.
6. **Key Concept: Precedence in DNS Resolution:** Remember that the local `hosts` file is checked before a DNS server is queried. This is why modifying it is an effective form of client-side DNS poisoning.
