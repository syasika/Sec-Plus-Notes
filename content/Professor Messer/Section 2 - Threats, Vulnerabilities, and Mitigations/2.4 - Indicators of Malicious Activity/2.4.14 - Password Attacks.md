# Password Attacks

## Overview
- **Definition**: Storing passwords as plaintext can lead to severe security breaches. Modern applications typically store passwords securely using hashing techniques.

### Plaintext / Unencrypted Passwords
- **Definition**: Some applications store passwords "in the clear," meaning they are not encrypted.
  - No encryption: The stored password can be read directly.
  - This is thankfully rare in modern applications.
- **Security Concern**: Anyone with access to the password file or database instantly has every credential in plaintext, allowing immediate exploitation of compromised accounts.
- **What to do if encountered**:
  - Do not store passwords as plaintext.
  - Use a better application that handles passwords securely.
  - Contacting the application developer might be an option, but it requires a rewrite to implement secure password storage.

## Hashing a Password
- **Purpose**: To store passwords securely by hashing them instead of storing them in plaintext.
- **What is a Hash**:
  - A cryptographic hash function takes an input (e.g., a password) and produces a fixed-length string of text, often referred to as a "message digest" or a "fingerprint."
- **Key Characteristics of Hashing for Passwords**:
    1. **Fixed-length output**: Regardless of the input size, the output hash will always be the same length.
    2. **Collision Resistance (hopefully)**: Different inputs should not produce the same hash.
       - While theoretically possible, good hashing algorithms make collisions extremely difficult to find.
    3. **One-way Trip**: It is computationally impossible to recover the original message (password) from the digest (hash).
       - Just like you can't reconstruct a person from their fingerprint.
    4. **Sensitivity**: Even a single character change in the input password results in a drastically different hash.
       - Example: `123456` produces one SHA-256 hash, while `1234567` produces a completely different one.

### How Passwords are Stored
- **Storage Method**: Password files in operating systems or databases store usernames and their corresponding password hashes. No original plaintext passwords are saved.

## Spraying Attack
- **Problem it addresses**: Traditional brute-force attacks on individual accounts can lead to lockouts after 3-5 failed attempts.
- **Mechanism**:
  - Attackers use a list of common passwords (e.g., "123456", "password", "qwerty").
  - They try one or a few of these common passwords against many different accounts across a system.
  - If a password doesn't work for one account, they move to the next account and try the same common password(s).
- **Attacker's Advantage**:
    - No lockouts: By trying only a few passwords per account, they avoid triggering lockout policies.
    - No alarms/alerts: This method often goes undetected by security systems looking for repeated failed attempts on a single account.
- **Goal**: To efficiently find accounts that use weak, common passwords without raising suspicion.

## Brute Force Attack
- **Definition**: An attacker tries every possible password combination until the correct hash is matched (or the login is successful).
- **Computational Cost**: Can be very time-consuming, especially with long, complex passwords and strong hashing algorithms.
- **Types of Brute Force Attacks**:

    ### a. Online Brute Force
    - **Method**: Repeatedly attempts to log in to an account directly through the login process.
    - **Characteristics**:
        - Very slow: Limited by network latency and server response times.
        - Account lockouts: Most systems implement account lockout policies after a number of failed attempts, making online brute-forcing impractical for single accounts.
        - Alarms/alerts: Multiple failed login attempts are often logged and can trigger security alerts.

    ### b. Offline Brute Force (Brute Force the Hash)
    - **Method**:
        1. Obtain a list of users and their password hashes from a compromised system (e.g., a password file, database dump).
        2. Take these hashes offline to the attacker's own system.
        3. Generate every possible password combination (starting from "a", "b", "c", then "aa", "ab", "ac", etc.).
        4. For each generated password, calculate its hash using the same hashing algorithm as the target system.
        5. Compare the calculated hash to the stored hashes. If a match is found, the original password has been "cracked."
    - **Characteristics**:
        - High Speed: Can be performed much faster as it's not limited by network or server-side lockout policies.
        - No lockouts/alarms: Since the attack is offline, it doesn't interact with the live system's security mechanisms.
        - Large Computational Resource Requirement: Requires significant processing power (often using GPUs) to generate and hash millions or billions of password combinations per second.

### Process Example:
- **Attacker has a target hash**: `5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8` (which is the hash for "password").
- They start hashing combinations:
    - `aaaaa` -> `ed968e840d10d2d313a870bc131a4e2c311d7ad09bdf32b3418147221f51a6e2` (No match)
    - `aaaab` -> `5ef1b1016a260f0c229c5b24afe87fe24a68b4c80f6f89535b87e0ca72a08623` (No match)
    - ... (many iterations) ...
    - `password` -> `5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8` (Match found!)

## Takeaways for Exam
1. **Plaintext Passwords are a Critical Vulnerability**: Understand why storing passwords in plaintext is catastrophic and that it's an absolute no-go in secure systems.
2. **Hashing is Fundamental for Password Security**:
    - Know the definition of a hash (fixed-length, message digest/fingerprint).
    - Understand the one-way nature of hashing – you cannot reverse a hash to get the original password. This is the primary reason it's used for passwords.
    - Recognize that even small changes in input lead to large changes in the hash (avalanche effect).
    - Be able to differentiate hashing from encryption (encryption is two-way, hashing is one-way).
3. **Spraying Attack vs. Brute Force**:
    - **Spraying**: Targets many accounts with few common passwords to avoid lockouts and detection. Goal is stealth and efficiency against weak passwords across a user base.
    - **Brute Force**: Targets one or more accounts with every possible password combination. Goal is to find the exact password, no matter how complex.
4. **Online vs. Offline Brute Force**:
    - **Online**: Directly interacts with the login mechanism. Slow, easily detected, prone to lockouts. Less effective.
    - **Offline**: Requires obtaining the password hashes first. Performed on the attacker's own hardware. Fast, undetectable by target system, no lockouts. Highly effective if hashes are acquired.
    - **Key difference**: Access to the hash file allows offline brute force, bypassing rate limiting and lockout policies.
5. **Defenses Implied (though not explicitly detailed as defenses in this video)**:
    - **Strong Hashing Algorithms**: Use modern, computationally intensive algorithms (like bcrypt, scrypt, Argon2, PBKDF2) that deliberately slow down the hashing process, making brute-force attacks take longer.
    - **Strong Passwords**: Users should be encouraged/forced to create long, complex, unique passwords to make brute-force and spraying attacks much harder.
    - **Account Lockout Policies**: Implement policies that lock accounts after a few failed login attempts to mitigate online brute-force and spraying attacks.
    - **Multi-Factor Authentication (MFA)**: Even if a password is breached, MFA adds another layer of security.
    - **Security Monitoring**: Monitor for unusual login patterns (e.g., many failed attempts from a single IP, or a single password tried across many accounts) to detect spraying attacks.
