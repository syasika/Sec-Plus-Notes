# Indicators of Compromise (IOC)

## Introduction to IOC

**Definition**: An event or piece of evidence indicating an intrusion or breach has occurred within a system or network. Confidence in an intrusion is high.

**Purpose**: IT security professionals use IOCs to detect and respond to security incidents. The phrase "he's calling from inside the house" aptly describes this scenario, as attackers are already in your system.

## Common Indicators of Compromise (IOCs)

### Unusual Network Activity

- **Significantly Large Amount of Traffic**: A large amount of data being transferred over a network at unusual times or to unusual destinations.
  
  - **Example**: A sudden surge in traffic during off-hours, possibly indicating data exfiltration.

### Change to File Hash Values

- **File Tampering**: Files on the system have had their hash values altered, suggesting they were modified or tampered with (e.g., malware altering system files).
  
  - **Example**: Monitoring file hashes can detect when a file has been changed, indicating potential malicious activity.

### Irregular International Traffic

- **Unusual Geographical Access**: Traffic originating from or destined for international locations that are not part of normal business operations.
  
  - **Example**: A user logging in from an unexpected country could indicate an attack.

### Changes to DNS Data

- **DNS Record Modifications**: Modifications to DNS records on your servers, which may indicate attackers trying to manipulate network traffic (e.g., redirecting users to malicious sites).
  
  - **Example**: Detecting unauthorized changes to DNS records can help prevent domain hijacking attacks.

### Uncommon Login Patterns

- **User Activity Anomalies**: User accounts logging in from unusual locations or at odd hours.
  
  - **Example**: A user logging into your system from a country where they do not normally work is suspicious.

### Spikes of Read Requests to Certain Files

- **Data Exfiltration Indicators**: Specific files or directories experiencing a sudden, high volume of read requests, possibly indicating an attacker is trying to gather data.
  
  - **Example**: Sudden spikes in file reads could suggest the system is being scanned for sensitive information.

## Specific IOC Scenarios

### Account Lockout

- **Credentials Not Working**: Users unable to log in with correct credentials.
  
  - **Exceeded Login Attempts**: An account automatically locks after too many incorrect password attempts. This can be suspicious if it happened without any legitimate user activity.
    
    - **Example**: An administrator locking an account due to excessive failed login attempts might indicate social engineering.

- **Account Administratively Disabled**: An account was manually disabled by an administrator.
  
  - **Large Concerns**: If this was done by someone outside your internal team, it could suggest a malicious intent. For example, attackers might lock an account and then impersonate the user to reset the password.
    
    - **Mitigation**: Strong processes for password resets are crucial to prevent unauthorized access.

### Concurrent Session Usage

- **Geographical Impossibility**: A single user logging in interactively from two geographically distant locations simultaneously is unlikely due to physical constraints.
  
  - **Example**: If a user logs into the system from Omaha, Nebraska, and Melbourne, Australia, at the same time, it raises suspicion.
  
    - **Detection**: Use log analysis tools (e.g., SIEM systems) to compare login locations and timestamps.

### Blocked Content

- **Persistence**: Attackers aim to maintain access by blocking security patches and other updates. This is like keeping the doors open for an intruder.
  
  - **Example**: Malware might block auto-update connections or prevent users from accessing security patch sites, making it difficult to remove the threat.
  
    - **Detection**: Look out for blocked content such as security patch sites or removal tools.

### Impossible Travel

- **Authentication Logs**: Logs record logon and logoff events, including location details. Unusual login times or locations can trigger alarms.
  
  - **Example**: A user logging in from Omaha, Nebraska, then three minutes later from Melbourne, Australia, should raise red flags.
  
    - **Detection**: Use SIEM systems to compare login locations and timestamps.

### Resource Consumption

- **Unusual System Activity**: Any activity by an attacker will consume system resources. Unusual spikes in network bandwidth at odd hours can indicate data exfiltration or reconnaissance.
  
  - **Example**: Monitoring firewall logs for unusual outbound transfers, including IP addresses and timeframes.

### Resource Inaccessibility

- **Server Availability Issues**: A server suddenly becomes unavailable, possibly due to an attacker exploiting a vulnerability that crashes the system.
  
  - **Example**: Encrypted data accessed only to find it is ransomware. Repeated failed login attempts can lock out legitimate users.
  
    - **Detection**: Continuously monitor resource usage and ensure logs are intact.

### Out-of-Cycle Logging

- **Unexpected Log Entries**: Logs or events occurring outside of normal operational schedules, such as patches installed at unusual times.
  
  - **Example**: An attacker might install a patch on a compromised system to secure their access from other attackers.
  
    - **Detection**: Use strong understanding of baseline behavior to identify deviations.

### Missing Logs

- **Log Integrity Issues**: Log entries or events missing during normal operation, which could be an attempt by the attacker to cover their tracks.
  
  - **Example**: Attackers might delete or alter logs to avoid detection. Authentication, file access, firewall, and server logs are crucial for forensic analysis.
  
    - **Detection**: Monitor log integrity and completeness.

### Published/Documented Data

- **Data Exfiltration Confirmation**: When private data appears on the internet, it confirms a successful breach.
  
  - **Example**: Ransomware attacks often result in both encrypted data release and public exposure of stolen data.
  
    - **Detection**: Publicly exposed organizational data is a clear indication of a breach.

# Exam Takeaways

1. **Define IOC**: Understand that an Indicator of Compromise (IOC) is an event indicating an intrusion with high confidence.
2. **Categorize & Recall Specific IOCs**:
   - **Network-based**: Unusual network activity, irregular international traffic, changes to DNS data, resource consumption spikes (bandwidth).
   - **System/File-based**: Change to file hash values, spikes of read requests to certain files, resource inaccessibility (server down, encrypted data).
   - **User/Authentication-based**: Account lockout (exceeded attempts, administrative disablement), uncommon login patterns, impossible travel, concurrent session usage.
   - **Log-based**: Out-of-cycle logging, missing logs.
   - **Public/External**: Published/documented data.

3. **Understand the "Why" for Each IOC**:
   - **Account Lockout**: Could be part of a brute-force or social engineering setup.
   - **Concurrent Sessions/I Impossible Travel**: Geographical impossibility for a single user, indicating an attacker's activity.
   - **Blocked Content**: Attacker trying to maintain persistence and prevent remediation.
   - **Resource Consumption**: Attacker activity (e.g., data exfiltration, malware operations).
   - **Resource Inaccessibility**: Attacker disrupting services, ransomware, or a failed exploit.
   - **Out-of-Cycle Logging**: Attacker performing actions outside normal IT schedules.
   - **Missing Logs**: Covering tracks to avoid detection.
   - **Published/Documented**: Confirmed data exfiltration often linked to ransomware.

4. **Importance of Baselines and Anomalies**: IOCs are anomalies that require a solid understanding of normal system and network behavior (baselines) for detection.

5. **Logging and Monitoring**: Comprehensive logging (authentication, file access, network traffic, system events) and continuous monitoring (SIEM systems, alerts) are foundational in detecting IOCs. Missing logs themselves can be an IOC.

6. **Attacker Persistence and Evasion**: Many IOCs reflect the attacker's efforts to achieve persistence or evade detection (e.g., blocked content).

7. **Social Engineering Connection**: Be aware that account lockouts can be part of a social engineering scheme to gain password resets.

8. **Ransomware Implications**: Understand how encrypted data and publicly published data are often direct results of ransomware tactics.
