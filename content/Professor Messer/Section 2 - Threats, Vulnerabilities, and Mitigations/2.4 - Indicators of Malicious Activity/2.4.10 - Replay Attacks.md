# Replay Attacks

## 1. What is a Replay Attack?

**Definition**: A replay attack involves capturing useful information transmitted over a network and reusing it to gain unauthorized access or achieve malicious goals.

**Mechanism**:
- Information (e.g., authentication credentials, session IDs) is sent between a client and a server.
- An attacker intercepts this data and then "replays" the captured information to trick the server into granting access or performing actions.

### Accessing Raw Network Data
- **Network Tap**: A physical device used to intercept network traffic.
- **ARP Poisoning**: Manipulating ARP tables to redirect traffic through an attacker's machine.
- **Malware**: Installing malicious software on a victim’s computer to capture data directly.

## 2. Pass the Hash

**Definition**: A specific type of replay attack focusing on password hashes during authentication.

**Scenario**:
1. **Client/Victim Authenticates**: A legitimate client sends their username and a *hashed* password (not the plain-text password) to a server for authentication.
2. **Attacker Captures**: An attacker, having gained access to network traffic, captures this authentication request, specifically the username and hashed password.
3. **Attacker Replays**: The attacker then sends their own authentication request using the captured username and hashed password.
4. **Server Grants Access**: Since the server receives a valid username and the correct hash, it authenticates the attacker, believing they are the legitimate client.

### Prevention
- **Encryption (End-to-End)**: Encrypting all traffic (e.g., using HTTPS) prevents attackers from seeing raw authentication data, including hashes.
- **Salting & Nonces with Session IDs**: Instead of just hashing the password, a "salt" (random data) is added to the password *before* hashing. A unique "session ID" or "nonce" is also incorporated into the authentication hash. This creates a **unique authentication hash each time** a user authenticates. The server is configured not to accept the same hash twice in a row, ensuring that replayed hashes are rejected.

## 3. Browser Cookies and Session IDs

### Cookies
- **Definition**: Small pieces of information stored on your computer by the browser when you visit websites.
- **Purpose**: Used for tracking, personalization, and session management.
- **Security Risk**: While cookies themselves are not executable, they can contain valuable information (e.g., usernames, session IDs) that could be exploited if accessed by an attacker.

### Session IDs
- **Definition**: Unique identifiers often stored within cookies that allow a web server to maintain a user's session across multiple browser requests without re-authenticating each time.
- **Vulnerability**: If an attacker obtains a valid session ID, they can potentially impersonate the legitimate user.

## 4. Session Hijacking (Sidejacking)

**Definition**: An attack where an attacker captures a legitimate user’s session ID and uses it to take over their active web session.

**Scenario**:
1. **Victim Authenticates**: A user successfully authenticates with a web server (e.g., by entering username and password).
2. **Server Issues Session ID**: The web server sends back a unique session ID, often stored in a cookie on the victim's computer.
3. **Attacker Captures Session ID**: An attacker intercepts and captures this session ID (e.g., via packet sniffing or exploits).
4. **Attacker Replays Session ID**: The attacker then sends requests to the web server using the captured session ID.
5. **Server Grants Access**: The web server recognizes the session ID as valid and active, believing the requests are coming from the legitimate, authenticated user.

### Methods for Header Manipulation
- **Information Gathering Tools**:
    - **Wireshark**: A packet analyzer to capture and inspect network traffic, revealing headers and cookies.
    - **Kismet**: A wireless network detector, sniffer, and intrusion detection system useful for capturing wireless traffic.
- **Exploits**: Cross-Site Scripting (XSS) can inject malicious scripts into websites to steal cookies/session IDs from other users.
- **Tools to Modify Headers/Cookies**:
    - Tamper
    - Scapy: A packet manipulation program
    - Cookies Manager+ (Firefox add-on for viewing and modifying cookies)

## 5. Preventing Session Hijacking

### End-to-End Encryption (Ideal Solution)
- **Method**: Use HTTPS for all connections between the client and web server.
- **Benefit**: Encrypts communication, preventing attackers from capturing or viewing session IDs in transit.
- **Considerations**:
    - Requires additional processing load on the web server.
    - Many websites are now HTTPS-only by default.
    - Browser extensions like "HTTPS Everywhere" can force HTTPS connections when available.

### Partial Encryption (Partial Solution)
- **Method**: Use a Virtual Private Network (VPN).
- **Benefit**: Encrypts traffic from your device to the VPN concentrator, protecting it over local or untrusted networks (like public Wi-Fi).
- **Limitations**: The traffic is decrypted at the VPN concentrator. The remaining part of the journey from the VPN concentrator to the destination server is still in the clear if HTTPS is not used.

## Takeaways for Exam Preparation

1. **Define Replay Attack**: Understand it as capturing and reusing network data (authentication, session IDs) to impersonate a legitimate user.
2. **Know How Attackers Obtain Data**: Be familiar with methods like network taps, ARP poisoning, and malware. Recognize that the capture phase often involves on-path attacks or system compromise.
3. **Understand "Pass the Hash"**:
    - It's a specific replay attack for authentication.
    - The attacker doesn't need the plaintext password; just the hash.
    - **Key Defense**: Use unique, salted hashes with nonces/session IDs for each authentication attempt to prevent reuse.
4. **Cookies and Session IDs are Prime Targets**:
    - Cookies store critical session information, while session IDs maintain user sessions.
    - Although not executable, cookies contain sensitive data that can be exploited.
5. **Session Hijacking (Sidejacking) Mechanics**:
    - Attacker captures a valid session ID after initial authentication.
    - Uses the ID to impersonate the user, bypassing login credentials.
6. **Methods for Header Manipulation/Hijacking**:
    - Information Gathering: Wireshark, Kismet (packet sniffers).
    - Exploits: Cross-site scripting is common for stealing cookies.
    - Tools: Tamper, Scapy, browser add-ons like Cookies Manager+ are used for manipulating headers and cookies.
7. **Primary Defense Against Session Hijacking**:
    - End-to-End Encryption (HTTPS): Most effective method; prevents session IDs from being captured in the clear.
    - Partial Encryption (VPN): Provides protection over the initial leg of the journey but traffic can still be vulnerable after the VPN concentrator if not using HTTPS.
8. **Key Principle**: The goal is to make each authentication or session token unique and non-reusable, or to encrypt it so it cannot be intercepted.
