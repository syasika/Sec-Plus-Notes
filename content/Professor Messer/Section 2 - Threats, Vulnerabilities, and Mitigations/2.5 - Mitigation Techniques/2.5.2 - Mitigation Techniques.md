# Mitigation Techniques

Mitigation is the process of reducing the impact of a security event or a potential security event. This section explores various techniques used to achieve this.

## 1. Patching

- **Purpose:** Essential for maintaining system stability and addressing security fixes.
- **Mechanism:** Addresses known vulnerabilities before they can be exploited.
- **Types of Updates:**
    - **Monthly Updates:** Regular, incremental updates (e.g., Microsoft Patch Tuesday). Crucial for ongoing security.
    - **Third-Party Updates:** Patches from application developers (e.g., Adobe, Java) and device drivers.
    - **Auto-Update:**
        - Convenient for home users.
        - Not always the best option for large organizations due to potential compatibility issues. Organizations often test patches in a controlled environment before widespread deployment.
    - **Emergency Out-of-Band Updates:**
        - Issued outside regular schedules.
        - Critical for zero-day vulnerabilities or when attackers are actively exploiting significant unpatched openings.

- **Benefit:** Prevents attacks by closing known security gaps and improves system stability.

## 2. Encryption

- **Purpose:** Protects application data files from unauthorized access by rendering them unreadable without the correct key.
- **Levels of Encryption:**
    - **File System Encryption (EFS):** Integrated directly into the operating system's file system, encrypting specific files or folders. Example: Windows EFS.
    - **Full Disk Encryption (FDE):** Encrypts everything on the drive, including the operating system and user files, protecting data even if the physical storage device is stolen. Examples: BitLocker (Windows), FileVault (macOS).
    - **Application Data Encryption:** Managed by the application itself, ensuring that data stored by the application is protected even if the underlying file system or disk is not encrypted or if the data is moved.

- **Benefit:** Protects data at rest and in transit from unauthorized disclosure, even if an attacker gains access to the storage medium.

## 3. Monitoring

- **Purpose:** Aggregates information from devices to identify and respond to security events.
- **Components:**
    - **Sensors:** Collect raw data (logs) from various sources:
        - Built-in sensors in devices (servers, switches, routers, firewalls).
        - Separate, dedicated devices (e.g., Intrusion Prevention Systems (IPS)).
        - Types of Logs:
            - Firewall logs (traffic filtering).
            - Authentication logs (login attempts, successes/failures).
            - Web server access logs (user requests, errors).
            - Database transaction logs (data modifications).
            - Email logs (sent/received messages).
    - **Collectors:** Consolidate log files from diverse systems into a central repository:
        - Examples: Proprietary consoles (for specific IPS/firewalls), SIEM Consoles, syslog servers.
    - **SIEM (Security Information and Event Manager):** A centralized system that collects, analyzes, and correlates security events from multiple sources. Includes a correlation engine to compare diverse sensor data, identify patterns, anomalies, and potential threats.

- **Benefit:** Provides visibility into network activity, enabling early detection of security incidents and facilitating incident response.

## 4. Least Privilege

- **Principle:** Rights and permissions should be set to the bare minimum necessary for a user or application to complete their objective.
- **Implementation:**
    - Users should only have the permissions required for their specific job role.
    - Applications should also run with minimal privileges.
    - Avoid granting administrative privileges routinely.
    - Permissions can be temporarily elevated when absolutely necessary, and then reverted.

- **Benefit:**
    - Limits the scope of malicious behavior.
    - Reduces the potential impact of a data breach if a user account is compromised.
    - Prevents unauthorized actions or accidental damage.

## 5. Configuration Enforcement

- **Purpose:** Ensures that systems connecting to the network comply with established security configurations and policies.
- **Mechanism:**
    - **Posture Assessment:** Performed each time a device attempts to connect to the network.
    - **Extensive Checks Include:**
        - Operating System (OS) patch version (is it up-to-date?).
        - EDR (Endpoint Detection and Response) version and signature status (are signatures current?).
        - Status of local firewall and EDR (are they configured and turned on properly?).
        - Certificate status (is the device trusted by the organization?).

- **Action for Non-Compliance:**
    - Systems failing the posture assessment are typically quarantined.
    - Quarantine usually involves placing the device in a private VLAN with limited network access, allowing the user or IT staff to make necessary corrections.
    - After corrections, the posture assessment is re-run to grant full network access.

- **Benefit:** Maintains a consistent and secure baseline configuration across all network-connected devices, reducing the attack surface.

## 6. Decommissioning

- **Purpose:** Safely and securely retires equipment, particularly storage devices, to prevent unauthorized access to sensitive data.
- **Requirement:** Should be a formal, documented policy.
- **Critical Warning:** Never simply throw data into the trash. Sensitive information can often be recovered from discarded devices.

- **Primarily Associated with Storage Devices:**
    - Hard Disk Drives (HDDs)
    - Solid State Drives (SSDs)
    - USB drives

- **Options for Physical Devices:**
    - **Recycle the device:** Applicable if the device will be reused within the organization. Requires securely wiping/formatting the drive to remove all data before reuse.
    - **Destroy the device:** Necessary if the device is leaving the organization or contains highly sensitive data. Methods include degaussing (for HDDs), shredding, or physical destruction (e.g., drilling into platters/chips).

- **Benefit:** Prevents data leakage and ensures compliance with data retention and disposal regulations.

# Takeaways for Exam Preparation

1. **Define Mitigation:** Understand it as reducing impact, not necessarily preventing.
2. **Patching is Proactive:** It's about fixing known vulnerabilities before they are exploited. Differentiate between regular, third-party, and emergency updates. Know why auto-updates aren't always suitable for enterprises.
3. **Encryption Protects Data:**
    - Know the difference between File System Encryption (EFS), Full Disk Encryption (FDE - BitLocker/FileVault), and Application Data Encryption.
    - Understand when each type is most appropriate (e.g., FDE for laptops that might be lost/stolen, EFS for specific sensitive files, App-level for critical application data).
4. **Monitoring for Visibility:**
    - Identify the sources of security data (sensors, logs from various devices).
    - Understand the role of SIEMs in collecting, analyzing, and correlating diverse log data. The "correlation engine" is key here.
5. **Least Privilege is Fundamental:**
    - This is a core security principle.
    - "Give users only what they need to do their job, no more."
    - Crucial for limiting the blast radius of a compromised account or malicious software.
    - Temporary privilege elevation is a best practice.
6. **Configuration Enforcement Ensures Compliance:**
    - Know the concept of a Posture Assessment – checking device health/compliance upon connection.
    - Be aware of the types of checks performed (OS patches, EDR status, firewall, certificates).
    - Understand the consequence of non-compliance: quarantine (e.g., private VLAN) until remediation.
7. **Decommissioning Secures End-of-Life Assets:**
    - Emphasize the importance of a formal policy for retiring equipment.
    - The primary concern is data sanitization/destruction on storage devices.
    - Differentiate between recycling (secure wipe for internal reuse) and physical destruction (for external disposal or highly sensitive data). Know examples of destruction methods (drilling, degaussing, shredding).
