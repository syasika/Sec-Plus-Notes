# Segmentation and Access Control

## Overview
- **Definition**: Refers to strategies employed to limit network access and protect data from unauthorized use.
- **Purpose**: To improve network management, enhance security, and ensure compliance with regulatory standards.

## Segmenting the Network

### Types of Segmentation
1. **Physical Segmentation**
    - **Example**: Different physical network cables connecting to different switches or routers.
2. **Logical Segmentation (VLANs)**
    - **Example**: Virtual Local Area Networks on network switches. Devices on different VLANs cannot communicate without a router, even if connected to the same physical switch.
3. **Virtual Segmentation**
    - **Example**: Virtual networks like AWS VPCs and Azure VNets that logically isolate virtual machines and resources.

### Reasons for Network Segmentation

#### Performance
- **High-bandwidth Applications**
    - **Benefit**: Prevents traffic from other users or applications from affecting the performance of critical applications.
    - **Example**: A dedicated segment for video conferencing or large data transfers.

#### Security
- **Strategic Segmentation**
    - Limits lateral movement of attackers within the network.
- **Principle of Least Privilege**
    - Users should only have access to resources necessary for their job.
    - **Example**: Users do not communicate directly with database servers; instead, they use an application server that communicates with the database.
- **Implementation**
    - Achieved using firewall rules or Access Control Lists (ACLs) to limit who can access specific servers or services.
    - **Example**: Only allowing SQL and SSH applications in the core network for database management.

#### Compliance
- **Mandated Segmentation**
    - Required by regulatory standards or internal policies.
    - **Example**: PCI DSS compliance mandates strict segmentation for systems handling credit card information to minimize breach scope.
- **Easier Change Control**
    - Changes in one segment have a reduced impact on other segments, simplifying management and reducing risk.

## Access Control Lists (ACLs)

### Definition
A set of rules that allow or disallow traffic based on predefined criteria. ACLs are fundamental for implementing network segmentation and access control.

### How ACLs Work
- **Allow or Disallow Traffic**
    - Explicitly define what traffic is permitted and denied.
- **Grouping Categories**
    - Rules based on various traffic characteristics:
        - Source IP address: Where the traffic originates.
        - Destination IP address: Where the traffic is intended to go.
        - Port number: The specific service being accessed (e.g., TCP port 80 for HTTP, 443 for HTTPS).
        - Time of day: Restricting access during certain hours.
        - Application: Identifying traffic based on the application protocol.
        - User/Group: Limiting access based on authenticated user identities.

### Implementing ACLs
- **Network Devices**
    - Routers and switches use ACLs to filter traffic between network segments or VLANs.
- **Operating Systems**
    - Used to control access to files, folders, and system resources.
    - **Example**: Setting permissions for "Bob to read files," "Fred to access the network," or "James to access network 192.168.1.0/24 using TCP ports 80, 443, and 8088."
- **Granular Controls**
    - ACLs allow administrators to create very specific and detailed rules for access.

### Important Considerations
- **Caution during Configuration**
    - Be careful when configuring ACLs; a misconfiguration can accidentally lock out legitimate users or even administrators.
    - **Best Practice**: Always test changes thoroughly and have a rollback plan.

## Application Allow List / Deny List

### Allow List (Whitelisting)
- **Philosophy**: Nothing runs unless it's explicitly approved.
- **Nature**: Very restrictive.
- **Benefit**: Highly secure as it prevents unknown or unauthorized applications, including most malware.
- **Drawback**: Requires significant administrative overhead to maintain and approve every legitimate application.

### Deny List (Blacklisting)
- **Philosophy**: Everything runs except what's on the "bad list."
- **Nature**: Less restrictive than an allow list.
- **Benefit**: Easier to manage for environments with many legitimate applications.
- **Drawback**: Only effective against known bad applications; new or unknown malware might bypass the deny list until its signature is added.

### Examples of Allow and Deny Lists (Operating System Decisions)

#### Methods for Defining Rules
1. **Application Hash**
    - **Mechanism**: A unique cryptographic identifier (hash) is generated for each application.
    - **Rule**: Only allows applications with a specific, approved hash to run.
    - **Security**: If any part of the application changes, its hash will change, and the rule will no longer apply, thus blocking execution.

2. **Certificate**
    - **Mechanism**: Applications are digitally signed by their publishers using a digital certificate.
    - **Rule**: Allows applications that are digitally signed by trusted publishers (e.g., Microsoft, Adobe, Google).
    - **Security**: Trust is placed in the publisher; if an application isn't signed by an approved publisher, it's blocked.

3. **Path**
    - **Mechanism**: Specifies the directory or folder from which an application can run.
    - **Rule**: Only allows applications to run if they are located in approved folders.
    - **Security**: Prevents users from running unauthorized applications from unapproved locations (e.g., personal download folders, USB drives).

4. **Network Zone**
    - **Mechanism**: Operating systems classify networks into zones (e.g., Private, Public).
    - **Rule**: Applications may be allowed or disallowed based on the network zone the system is currently connected to.
    - **Security**: Allows for different security postures depending on the network environment.

## Takeaways for Exam Preparation

1. **Define and Differentiate Segmentation Types**
    - Understand physical, logical (VLANs), and virtual segmentation.
    - Be ready to give examples of each type.

2. **Explain the *Why* of Segmentation**
    - Memorize the three core reasons: Performance, Security, and Compliance.
    - For each reason, provide specific examples or benefits:
        - High-bandwidth apps for performance
        - Limiting lateral movement for security
        - PCI DSS for compliance

3. **Master ACLs**
    - Know what an ACL is (allow/disallow traffic).
    - Understand the various criteria used in ACLs (IP addresses, ports, time, application, user).
    - Be aware of the critical warning: ACL misconfiguration can lock you out.
    - Recognize that ACLs apply at both network and operating system levels.

4. **Compare and Contrast Allow Lists vs. Deny Lists**
    - Know their core philosophies ("nothing runs unless approved" vs. "everything runs except bad stuff").
    - Understand their respective strengths (high security vs. flexibility) and weaknesses (high overhead vs. vulnerability to new threats).
    - Be able to identify which type of list an antivirus software uses (deny list).

5. **Identify OS-Level Application Control Methods**
    - List and explain the four methods discussed: Application Hash, Certificate, Path, and Network Zone.
    - For each method, understand how it works to enforce allow/deny policies and its specific security benefit.

6. **Scenario-Based Questions**
    - Be prepared for questions that present a scenario and ask you to apply segmentation or access control principles:
        - Example: "An organization needs to protect sensitive customer data while allowing employees to access a wide range of applications. Which segmentation strategy and application control method would be most appropriate and why?"
        - Example: "Describe how VLANs contribute to both network performance and security."
