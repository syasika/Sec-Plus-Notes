# Buffer Overflows

## Overview
- **Definition**: A buffer overflow is an attack where more data than expected is written into a designated memory buffer, causing excess data to overwrite adjacent memory areas.
- **Vulnerabilities**: This can lead to crashes or the execution of arbitrary code.

### Developer Responsibility & Bounds Checking 
- **Key Concept**: **Bounds Checking**
  - **Purpose**: Developers should implement checks to ensure that data being written to a buffer does not exceed its allocated size.
  - **Attacker Strategy**: Attackers look for applications where proper bounds checking is missing, creating openings for buffer overflow attacks.
  - **Goal of Attacker**: To modify the application's intended behavior by overwriting critical memory regions.

### Complexity of Exploits 
- Buffer overflows are not simple exploits. They require:
  - **Crashing**: Often leading to system or application crashes (Denial of Service).
  - **Precision**: Precise knowledge of memory layout and exact data needed.
  - **Time-Consuming**: Crafting a non-crashing, successful exploit takes significant time.

### Repeatable Buffer Overflows 
- **Definition**: A buffer overflow that is repeatable and consistently provides the attacker with a specific advantage.
- **Impact**: A repeatable buffer overflow means a system can be reliably compromised to perform actions beneficial to the attacker.

## Example: Privilege Escalation

### Scenario
- **Variables**:
  - `A`: An 8-byte buffer, currently a null string (`00`).
  - `B`: A 2-byte integer holding the value `1979` (hex `07 BB`).

### Application Logic
- If `Variable B` < 2000: User/Guest rights.
- If `Variable B` > 24000: Administrator rights.

**Attacker's Goal**: Change `Variable B` to a value greater than 24000 to gain administrator rights. **Vulnerability**: `Variable A` lacks proper bounds checking.

### Attack Steps
1. Identify the lack of bounds checking for `Variable A`.
2. Craft an input, such as "excessive", which is 9 characters long.
3. The application attempts to store "excessive" into `Variable A`.

**Memory State Before Attack:**

| Variable Name | Value                               | Hex Value (Bytes)                                               |
| :------------ | :---------------------------------- | :-------------------------------------------------------------- |
| A             | `[null string]`                     | `00 00 00 00 00 00 00 00`                                       |
| B             | `1979`                              | `07 BB`                                                         |

**After Overflow:**

1. The first 8 characters of "excessive" ('e', 'x', 'c', 'e', 's', 's', 'i', 'v') are stored in `Variable A`.
   - Hex values: `65 78 63 65 73 73 69 76`
2. The 9th character ('e') overflows into the first byte of `Variable B`.
   - Hex value for 'e': `65`
3. The original first byte of `Variable B` (`07`) is overwritten by `65`.
4. The second byte of `Variable B` (`BB`) remains unchanged.

**New Memory State:**

| Variable Name | Value             | Hex Value (Bytes)                                               |
| :------------ | :---------------- | :-------------------------------------------------------------- |
| A             | 'e', 'x', 'c', 'e', 's', 's', 'i', 'v' | `65 78 63 65 73 73 69 76`                                       |
| B             | `25856`           | `65 00` (The `BB` was replaced by `00` in the example; Professor Messer simplifies by showing `65 00` rather than `65 BB` which would be `25859`. The core concept of *overwriting* is the same.) |

**Result of Overflow:**
- `Variable B` now has the hex value `65 00`.
- Converting `0x6500` to decimal: `(6 * 16^3) + (5 * 16^2) + (0 * 16^1) + (0 * 16^0) = 24576 + 1280 = 25856`.
- Since `25856` is greater than `24000`, the attacker successfully gains administrator rights without needing credentials.

## Key Takeaways for Exam

1. **Core Definition**: Understand that a buffer overflow involves writing too much data into a fixed-size memory buffer, causing it to spill into adjacent memory.
2. **Mechanism**: Primarily occurs due to a lack of bounds checking by developers.
3. **Impacts**:
   - **Denial of Service (DoS)**: Uncontrolled overflows often crash applications or systems.
   - **Privilege Escalation**: An attacker can overwrite variables controlling user permissions to gain higher access.
4. **Exploit Difficulty**: While the concept is simple, crafting a useful and repeatable buffer overflow exploit requires precise knowledge of memory layout and careful payload construction to avoid crashes and achieve specific goals.
5. **Mitigation**: Primary defense includes secure coding practices with robust bounds checking for all memory writes. Other mitigations include Data Execution Prevention (DEP), Address Space Layout Randomization (ASLR), and Stack Canaries.

6. **Example Understanding**: Be able to explain the example involving `Variable A` and `B`, and how overwriting `Variable B`'s value led to privilege escalation. Understand the hexadecimal representation and its impact on the decimal value.
   - **Key Insight**: The attacker doesn't directly write to `Variable B`. They exploit the adjacent buffer `A` to indirectly modify `B`.
