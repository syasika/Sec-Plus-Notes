# Zero-Day Vulnerabilities

## Introduction to Vulnerabilities
Most applications and operating systems come with inherent **security vulnerabilities** that remain undiscovered for some time. Eventually, these vulnerabilities are found by either **good guys** or **attackers**.

### Security Researchers/Ethical Hackers (Good Guys)
- Work to identify and report vulnerabilities.
- Practice **responsible disclosure**: they share their findings with the software developers/vendors.
- This allows vendors to develop and release **patches** to fix issues before widespread exploitation.

### Attackers
- Also actively search for vulnerabilities but do not disclose them.
- Motivated by personal gain, such as launching attacks or stealing data.
- Keep undiscovered security holes secret until they can be exploited.

## Zero-Day Attacks Explained

### Definition and Key Characteristics
A **zero-day attack** exploits a previously unknown vulnerability. The main characteristics are:
- Attackers search for these unknown vulnerabilities.
- Develop specific **exploits** to take advantage of the flaws.
- At the time of the attack, the vendor is unaware.
- No patches or mitigation methods exist.

### "Zero-Day" Meaning
The term "zero-day" refers to the fact that vendors have had zero days to fix the issue since it wasn't known until the attack occurred. This creates a race between attackers and the security community/vendors to discover and mitigate the vulnerability first.

### Defense Challenges
Traditional security tools, like signature-based antivirus, are ineffective against zero-day exploits because no signatures exist yet. Defensive strategies must rely on behavioral analysis and robust security practices.

## Common Vulnerabilities and Exposures (CVE)

- **CVE**: A publicly maintained list for tracking and standardizing cybersecurity vulnerabilities.
- Purpose: To provide a common identifier for publicly known information security vulnerabilities.
- **Website**: [cve.mitre.org](http://cve.mitre.org/)
- Note: Zero-days only receive CVE identifiers after being discovered and disclosed.

## Examples of Zero-Day Attacks

### April 2023 - Chrome Zero-Day
- **Vulnerability Type**: Memory corruption leading to a sandbox escape.
- **Impact**: Allowed attackers to bypass the browser's security sandbox, potentially gaining greater control over the system.

### May 2023 - Microsoft Zero-Day Patch
- **Vulnerability Type**: Flaw in Secure Boot.
- **Impact**: Attackers could run UEFI-level self-signed code, circumventing secure boot. This is a low-level and powerful exploit.

### May 2023 - Apple iOS and iPadOS Zero-Days
- Apple released three separate zero-day patches for its mobile operating systems.
- **Vulnerability Types**:
    - Sandbox escape: Similar to Chrome, allowing malicious apps to break out of their confined environment.
    - Disclosure of sensitive information: Enabling attackers to access confidential data.
    - Arbitrary code execution: Allowing attackers to run their own code on the device.
- Note: These particular Apple zero-days were actively exploited before patches were available.

## Exam Takeaways

1. **Core Definition**: A **zero-day vulnerability** is a software flaw unknown to the vendor, meaning no patch exists. A **zero-day attack** targets such an unknown vulnerability.
2. **Key Distinction**: The defining characteristic of a zero-day is the lack of vendor awareness and available patches at the time of the attack.
3. **Threat Model**: Attackers seek these vulnerabilities for exclusive exploitation and personal gain, keeping them secret from vendors. Ethical researchers aim to find and report them responsibly to allow for patching.
4. **Defense Difficulty**: Zero-day attacks are exceptionally hard to defend against because traditional signature-based security tools cannot detect what is unknown. Defense relies on behavioral analysis, anomaly detection, and robust security practices.
5. **Lifecycle of a Zero-Day (Hypothetical)**
    - Vulnerability exists in software.
    - Attacker discovers it before the vendor.
    - Attacker develops an exploit and launches an attack.
    - Security researchers/vendor discover the vulnerability.
    - Vendor develops and releases a patch.
    - Users apply the patch, and the vulnerability is no longer a "zero-day".
6. **CVE**: A public database for tracking disclosed vulnerabilities. Zero-days will eventually get CVE IDs once they are known and documented.
7. **Real-World Impact**: Zero-days are regularly discovered and actively exploited by sophisticated threat actors (e.g., in web browsers, operating systems like Windows and iOS). Be aware of examples like memory corruption, sandbox escapes, and UEFI-level code execution.
8. **Mitigation (Post-Discovery)**: Once a zero-day is identified, vendors must rapidly respond to create and deploy patches. Until patches are available, organizations might implement temporary workarounds or rely on advanced threat detection systems.
