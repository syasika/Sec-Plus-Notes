# Misconfiguration Vulnerabilities

## 1. Open Permissions
- **Definition**: Data or resources left accessible to unauthorized individuals due to incorrect access controls.
- **Risk**: Very easy for attackers to find and exploit.
    - Hackers use this as a method of **reconnaissance** to find exposed data.
- **Increasingly Common with Cloud Storage**:
    - Statistical chance of finding an open permission.
    - **Example (June 2017)**: 14 million Verizon records exposed.
        - A third-party vendor left an **Amazon S3 data repository open** without password protection.
        - **Fortunately**, a security researcher found the data before malicious attackers did, allowing it to be secured.
- **Key Takeaway**: Always verify and secure permissions on all data, especially in cloud environments.

## 2. Unsecured Admin Accounts
- **Definition**: Administrative or superuser accounts with weak, default, or easily guessable passwords.
- **Examples of Admin Accounts**:
    - **Linux**: Root account
    - **Windows**: Administrator or superuser account
- **Misconfiguration Vulnerability**:
    - Intentionally configuring an easy-to-hack password (e.g., "123456", "ninja", "football").
    - Default operating system settings often prevent creating accounts with no passwords, but weak passwords are a common user error.
- **Best Practices for Security**:
    - **Disable direct login to the root/administrator account**:
        - Users should first log in with a normal user account.
        - Then, use elevated access commands like `su` or `sudo` (Linux) or "Run as administrator" (Windows) when necessary.
    - **Protect accounts with root or administrator access**:
        - There should be **very few** such accounts.
        - This limits the attack surface and makes it harder for attackers to compromise.

## 3. Insecure Protocols
- **Definition**: Network communication protocols that transmit data "in the clear" (unencrypted), making it vulnerable to eavesdropping.
- **Protocols Not Encrypted by Default**:
    - **Telnet**: Remote terminal access
    - **FTP (File Transfer Protocol)**: File transfer
    - **SMTP (Simple Mail Transfer Protocol)**: Sending email
    - **IMAP (Internet Message Access Protocol)**: Receiving email
- **Verification with Packet Capture (e.g., Wireshark)**:
    - Allows you to view everything sent over the network.
    - If you see `HTTP` instead of `HTTPS`, or unencrypted credentials for Telnet, FTP, etc., it's insecure.
    - **Example**: A live demonstration at a security conference where unencrypted usernames, passwords, and other sensitive information transmitted over the conference Wi-Fi were captured and displayed publicly.
- **Solution**: Use the **encrypted versions** of these protocols:
    - **SSH (Secure Shell)** for remote access (replaces Telnet)
    - **SFTP (SSH File Transfer Protocol)** or **FTPS (FTP Secure)** for file transfer (replaces FTP)
    - **SMTPS (Simple Mail Transfer Protocol Secure)** for sending email (replaces SMTP)
    - **IMAPS (Internet Message Access Protocol Secure)** for receiving email (replaces IMAP)
    - **HTTPS (Hypertext Transfer Protocol Secure)** for web browsing (replaces HTTP)

## 4. Default Settings
- **Definition**: Leaving factory-set usernames and passwords on applications and network devices.
- **Problem**: Every application and network device has a default login. A significant number of these are never changed by users or administrators.
- **Mirai Botnet Example**:
    - **Takes advantage of default configurations**.
    - Specifically targets and takes over **Internet of Things (IoT) devices** (e.g., cameras, routers, doorbells, garage door openers, DVRs).
    - Contains a list of **60+ common default configurations** (username/password pairs).
    - If an IoT device on a network still uses its default credentials, Mirai can compromise it.
    - **Impact**: Compromised devices become part of a botnet, used for large-scale Distributed Denial of Service (DDoS) attacks.
    - **Open-source release**: Mirai's code was released as open-source, allowing both researchers and attackers to easily use and adapt it.
- **Key Takeaway**: **Always change default usernames and passwords** on all new devices and applications immediately after installation.

## 5. Open Ports and Services
- **Definition**: Network ports left open and accessible, allowing inbound connections to services running on a server or device.
- **Risk**: Each open port is a potential entry point for attackers. It's like leaving a window open in your house.
- **Management**:
    - Often managed with a **firewall**.
    - Firewalls manage traffic flows, allowing or denying connections based on port number, application, source/destination IP, etc.
- **Misconfiguration Vulnerability**:
    - **Firewall rulesets can be complex**: It's easy to make a mistake in configuring firewall rules, unintentionally opening a port or allowing access where it shouldn't be.
    - If a port is open, attackers are bound to find it.
- **Best Practices**:
    - **Limit the number of open ports** to only those absolutely necessary for legitimate services.
    - **Always test and audit firewall rulesets periodically**:
        - Double-check and triple-check configurations.
        - Use port scanners and vulnerability assessments to confirm only intended ports are open.

---

## Takeaways for Exam (Key Points to Remember)

1.  **Misconfiguration is a HUGE Vulnerability**: It's not always about sophisticated hacks; simple errors in setup can expose critical data and systems.
2.  **Cloud Storage ≠ Automatic Security**: Just because data is in the cloud (e.g., Amazon S3) doesn't mean it's secure. Permissions must be explicitly managed and secured. (Remember Verizon example).
3.  **Admin Accounts are Prime Targets**: Root/Administrator accounts are powerful.
    *   **NEVER use weak/default passwords**.
    *   **Disable direct login** to these accounts; use `su`/`sudo` or "Run as administrator" after logging in as a regular user.
    *   **Principle of Least Privilege**: Minimize the number of accounts with administrative access.
4.  **Know Your Protocols**: Differentiate between secure and insecure protocols.
    *   **Insecure (Cleartext)**: Telnet, FTP, SMTP, IMAP, HTTP
    *   **Secure (Encrypted)**: SSH, SFTP, FTPS, SMTPS, IMAPS, HTTPS
    *   Be able to identify insecure traffic via packet capture (like the DefCon "Wall of Sheep").
5.  **Default Settings are Dangerous**: Attackers (like the Mirai botnet) actively scan for devices still using default credentials, especially IoT devices. **Always change them!**
6.  **Firewalls Need Careful Management**:
    *   Services open ports.
    *   Firewalls control access, but complex rulesets can lead to misconfigurations.
    *   **Regular testing and auditing** of firewall rules are essential to ensure only necessary access is granted.
